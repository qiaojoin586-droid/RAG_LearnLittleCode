## 新命令与明确范围

prepare-keyring-rotation 从现有密钥文件生成独立的新文件：新增一个随机 Fernet 密钥作为 active_version，原版本与内容全部保留。源文件不变，目标存在或版本名已存在时拒绝；写入/同步失败不产生目标，自己的临时文件会清理；并发准备同一个目标只有一个成功。不会自动修改环境变量、应用当前实例、密文行或配置发布。

inspect-keyring 为只读盘点，需现行 active 配置管理员，复用 config.publish 授权；它是本地受控入口，没有新增 HTTP 端点或客户端认证绕过参数。报告包括：

- 每个密钥版本的凭据状态计数，以及仍在重放窗口内的配置/个人记忆请求计数。
- 缺失版本；可选逐条验证 scope/id/origin/credential_version 绑定的解密结果。
- 解密失败总数、最多 100 条失败的版本/ID，以及是否截断；未请求解密时结果为 null。
- 个人记忆表是否存在、只读事务标识、key_removal_authorized=false；没有密钥正文、明文 API Key、HMAC 值、个人记忆正文或文件路径。

版本名存在只证明引用材料可查，不证明它是正确密钥；错误材料即便使用同名版本也会在解密检查中失败。检查失败退出码为 2；文件、授权或数据库操作失败为 1。缺个人记忆表时如实报告，不能据此认为已检查它的引用。盘点不会删除旧版本，也不是在线切换许可。

## 文件与发布门禁

Keyring.load 增加封闭文件格式与歧义检查：仅 active_version/keys 两个根字段，拒绝重复 JSON 字段/版本、无效类型/编码/密钥、超 1 MiB 文件或超过 128 个版本。缺文件、错误材料均明确失败，不生成替代密钥；解析错误上下文不携带原始输入。允许 Windows 常见 UTF-8 BOM。

准备过程使用同目录 mkstemp、flush/fsync 后以 os.link 安装新文件，已有目标不会被覆盖；不支持硬链接的文件系统明确失败，不采用可能覆盖目标的降级方式。临时文件和目标目录仍须由部署 secret 管理。Python 接口依据见 [mkstemp](https://docs.python.org/3.12/library/tempfile.html#tempfile.mkstemp) 与 [os.link](https://docs.python.org/3.12/library/os.html#os.link)；认证加密沿用项目现有 [Fernet](https://cryptography.io/en/stable/fernet/)，没有新增自定义加密算法。Windows ACL、挂载文件系统语义及断电后的持久性没有在本批证明。

publish/restore 在提交 release/head 前验证引用凭据可以使用当前密钥材料正确解密；缺少版本、错误密钥或损坏密文返回 50303，事务整体回滚，不留下新 release 或移动 head。这补齐了“行存在且状态有效，但当前文件无法读取它”的恢复缺口。

激活新 active_version 后，后续新建/替换的凭据写入新 key_version；原凭据行和旧快照保持原版本，依靠保留材料解密。旧 HMAC 重放按记录中的版本验证；旧 reauth proof 因签名版本不再是 active 而失效，需要重新认证。普通 Key 替换继续走新凭据、能力测试与发布；本批不批量复制或原地重加密历史密文，不提供自动删除旧主密钥入口，撤销语义不变。
