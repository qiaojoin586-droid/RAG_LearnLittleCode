# M1-I：候选配置生命周期与测试产物清理

日期：2026-11-17。本地开发，尚未上线。承接 [M1-H 通知管理](./M1_配置通知查询与死信补投_2026-11-17.md)，本批实现后台候选配置过期、退役及保留期后删除，并按用户要求清理测试生成的临时产物。运行中的前后端未重启；新增维护代码在下次启动按显式配置加载。本轮没有启用或对业务库执行退役/删除，也没有新增数据库迁移。

## 已实现的候选维护

CandidateLifecycleWorker 使用现有控制存储与单进程管理租约。每批最多 20 个草稿，每个草稿、每类候选最多 100 行；游标只在事务提交后推进。常规每小时扫描，有分页/过期积压时 60 秒继续，失败整体回滚并在 60 秒后重试，日志只输出固定维护失败信息。

1. editing/validating/ready 超过 expires_at 后标记 expired，过期草稿不能再测试或发布。
2. 来源为 abandoned/expired/published 的未使用候选，检查引用后设置 retired/retired_at。published 来源里编辑时产生、最终未发布的候选也纳入扫描；实际 published profile/prompt 和 active 凭据不作为清理目标。
3. 退役满七天、再次通过引用检查且显式允许删除后，先删 profile/prompt，再删没有 profile 引用的凭据密文行，同时清理对应 draft_items。保持请求、验证、草稿、版本计数器和脱敏审计，不复用被删除的版本号。

引用保护包括 release_refs、实际历史发布 JSON、有效草稿 inventory 与实际 payload、有效验证证据/租约/截止、索引 build_profile、提示词恢复来源链、同进程凭据 HTTP 租约和未结束的撤销通知。历史发布从未被本任务清理，即使引用登记行缺失也用实际清单保护。删除前重新检查，不能仅凭“来源草稿已关闭”就删密钥。

撤销候选保持 revoked，只补充退役时间，不改回可用。无历史发布引用的 retired 候选不能跨草稿引用或重新取得发布资格。保留期后，读取已放弃且依赖已清理的草稿返回 HTTP 410 / DRAFT_REFERENCES_PURGED；原过期草稿沿用既有错误。

每次过期/退役/删除都与脱敏审计在同一事务，固定维护 actor 为 system:config-lifecycle，不冒用用户身份；审计只有对象种类、ID、来源及必要凭据版本，不含密文、Key 或提示词正文。审计/外键/存储失败全部回滚，不能留下半清理的 inventory 或成功记录。管理租约到期则本批不提交。

待处理的凭据撤销通知阻止清理；终态通知保留。已经清理的候选不能再人工补投撤销通知，返回 40923 / OUTBOX_TARGET_UNAVAILABLE，避免创建必然失败的新事件。该变化不恢复凭据或活动发布。

## 显式启用与维护账号

以下是部署配置说明，本轮没有修改业务 .env 或启用开关：

```text
AI_CONFIG_CANDIDATE_GC_ENABLED=true
AI_CONFIG_CANDIDATE_GC_PURGE=false
```

默认整个任务关闭；开启后默认只退役。正式删除还需显式设置 AI_CONFIG_CANDIDATE_GC_PURGE=true。生产环境必须注入 AI_CONFIG_MAINTENANCE_DATABASE_URL，指向同一主机、端口、数据库类型和库名，使用不同于业务连接的维护账号。URL/凭据只通过部署 secret 注入，不写前端、请求或审计，也不输出底层解析异常。维护连接独立小连接池，关闭服务时先停任务再释放池。

代码校验独立账号和目标库，不自动授予权限；具体最小权限和权限撤销仍需部署验收。开发环境可显式使用已有本地连接。未配置生产维护连接、指向另一库或复用生产业务账号时明确拒绝，不悄悄使用业务账号删除。

扫描/保留周期与七天边界已由隔离夹具验证；“24 小时内退役”的实际容量目标仍需部署负载验收。慢批次超过管理租约会回滚并重试，不能用当前小规模测试代替生产吞吐/SLO 证明。

## 测试产物清理

只删除经过路径检查的 pytest 临时数据、pytest 缓存和 tests/__pycache__，包含项目根 pytest-of-HANXI、.pytest_tmp、.pytest_cache，以及各升级验证目录中的 pytest-* 子目录。清理脚本先检查绝对路径处于工作区内、没有 reparse point/链接、没有 Git 跟踪文件，再使用 PowerShell Remove-Item -LiteralPath 删除；不跨 shell 拼接路径。

保留所有测试源码、迁移/验证工具、JUnit/JSON 报告、manifest、失败复核记录、业务 data/logs、依赖环境和 .cache/service-runtime。未把“不影响运行”理解成删除整个测试体系；未删除来源不明的运行时缓存。清理前后汇总见本轮 cleanup-*.json，包含具体路径、文件数与字节数。

.gitignore 新增 .pytest_tmp/、pytest-of-*/、torchinductor_*/，防止常见本地生成目录混入待提交列表。后续测试会重新生成临时产物，本轮验证结束后再执行一次清理；报告和源文件不删除。
