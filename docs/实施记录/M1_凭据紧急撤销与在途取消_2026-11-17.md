# M1-G：凭据紧急撤销与在途取消

日期：2026-11-17。本地开发环境，尚未上线。承接 [M1-F 请求级向量绑定](./M1_请求级向量绑定与连接热更新_2026-11-17.md)，本批补齐指定凭据版本的管理员撤销、页面操作、同进程 HTTP 取消和持久事件重试。业务后端保持停止；本轮未对业务库迁移、授权、写入 Key、发布配置或撤销任何真实凭据。

## 用户操作与实际范围

模型配置页新增“凭据版本与紧急撤销”，主动读取后分页显示角色、版本、脱敏尾号、origin 和状态。配置读者可查看影响，只有配置管理员可执行撤销。影响窗口列出当前启用角色、潜在动态跟随角色、当前索引、历史发布数量和草稿关联数量；不解密 Key、不访问供应商。

用户选择固定原因、确认影响范围后再重新认证，提交服务端撤销。取消确认或认证不会发出撤销请求。网络失败重试同一目标/原因时保留幂等键，重新取得认证证明。页面提示成功并更新状态；当前角色表单未保存的提示词等编辑保留，撤销后的元数据刷新不会覆盖这些编辑。

撤销不可恢复，作用于本系统的一份 credential_revision_id 的全部引用，包括旧快照及历史配置。多个角色引用同一版本时一并受影响；其他凭据版本即使保存了相同的真实 Key，也不会自动撤销。尾号相同不能证明 Key 相同。页面不会替用户停用供应商侧的真实 Key；疑似泄露时仍需在供应商侧处理。无认证 Ollama 不生成凭据版本，也没有可撤销的 Key 对象；有认证服务按实际保存的凭据版本处理。

影响窗口不是全局冻结快照，读取后可以新增引用；最终撤销仍覆盖该版本的全部引用。草稿数量包含保留的历史登记引用，不保证都是当前有效草稿。动态角色列表示潜在影响，不声称每个动态角色都会选中此版本。

## 接口、权限与事务

新增/接通以下接口，公共前缀 `/api/v1/model-config`：

| 接口 | 权限及行为 |
| --- | --- |
| GET /credentials | config.read；分页脱敏凭据版本，包含撤销 epoch/时间 |
| GET /credentials/{id}/impact | config.read；读取上述引用影响，异作用域目标不返回 |
| POST /credentials/{id}/revoke | config.credential.revoke；新动作需 Idempotency-Key 和 X-Admin-Reauth |

服务端验证当前账户、grant、管理租约和重新认证。证明绑定 actor、当前 access_jti、system scope，时效最多 600 秒；浏览器只在内存使用。首次撤销在同一事务中完成：

1. 锁定目标凭据，写入 status=revoked、revoked_at，并递增 revocation_epoch。
2. 创建唯一 credential.revoked Outbox 事件，仅含目标版本 ID 与 epoch。
3. 将使用此版本的 pending/running 能力探测置为 cancelled，更新对应持久动作的终态回执，清除有效期。
4. 写入脱敏审计、请求回执并提交，不移动活动发布 head。

审计记录目标 ID、凭据版本、epoch、固定原因类别和原因 HMAC 指纹。API 的 reason 为非空文本、最长 512；非固定类别归为 operator_supplied，不保存自由文本正文。Key、密文、密码及 proof 均不进入撤销请求/审计/事件正文。

相同 actor/action/幂等键与相同输入重放原已提交回执，不重复授权新动作；读取重放仍要求现行配置读取权限。相同键不同目标或输入返回 40922。已撤销版本使用新键再次确认返回 already_revoked=true，不再增加 epoch 或重复事件；兼容已有 revoked/epoch=0 数据。撤销事务失败时不会先行通知 HTTP 注册表，数据库和正在进行的连接均不被这次失败动作改变。

成功回执为附件 E 的 CredentialRevocationResult：credential_revision_id、credential_version、status、revocation_epoch、dispatch_blocked=true、cancel_requested=true、already_revoked。不返回 remote_cancelled，也不承诺供应商已停止计算。验证通过的历史能力证据保持原样，不能因保留证据而绕过当前撤销检查。

## 旧快照、在途请求与向量缓存

配置快照仍固定模型和凭据版本，普通替换/发布不自动撤销旧版本。紧急撤销是独立动作：后续发送许可依据数据库当前状态与 epoch 检查，禁止自动切换到“最新 Key”。向量暖缓存读取也执行许可检查，不因没有新的模型 HTTP 调用而跳过撤销。

修正 MySQL REPEATABLE READ 下的一处竞态：运行时和能力探测最终许可对凭据使用当前共享读，避免此前用户/端点读取建立的旧一致性快照把已提交的撤销当成 active。共享锁在许可事务结束时释放，再进行网络请求，不把数据库事务拖过整个模型流。

新增凭据 HTTP 租约注册表和传输包装。租约先于受控发送许可登记，保持至响应关闭，覆盖等待响应头和逐次读取响应体。撤销提交后请求同进程对应租约停止；取消针对 HTTP 工作，调用方收到结构化 CREDENTIAL_REVOKED，不直接取消整条用户任务。LangChain 原始 client.stream、通用探测和向量适配器使用同一受控传输路径，响应流关闭时释放租约。

立即本地通知失败不回滚已经提交的撤销，由 Outbox 按既有有界重试/死信规则补发。事件处理重新读取已提交的 status/epoch，不依赖必须存在活动发布，因此尚未发布的候选凭据也能撤销。当前只支持已约束的 M1 单进程部署；此注册表不是跨进程广播。

许可检查与 HTTP 发送不构成分布式原子事务。撤销前已获许可的请求属于在途，注册表尽力取消；上游已经受理的内容、计算或效果不能撤回。即使取消通知延迟/重试，新的数据库许可仍拒绝已撤销版本。M2 多进程通知与状态巡检未在本批实现。

## 撤销后的修复

本批同时修正“活动配置已撤销便无法创建修复草稿”的恢复阻塞。现在允许从该发布创建草稿并逐项编辑，返回 CREDENTIAL_REVOKED、CREDENTIAL_EXPIRED、ENDPOINT_DENIED 等 publication_blockers，保留范围与候选归属校验。编辑尚未修复的草稿不等于获得使用资格：保留已撤销 Key 的模型重存、针对它的测试、发布及历史恢复仍拒绝。

恢复使用时，保存新 Key 创建新的候选凭据版本，更新所有必要绑定，通过当前版本能力测试后发布。旧版本保持 revoked，既有历史记录不改写；单纯恢复到引用它的旧发布不能复活凭据。
