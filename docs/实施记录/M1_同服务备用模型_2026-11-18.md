# 发布配置中的同服务备用模型

2026-11-18 实施，承接同端点有限重试。模型配置页的角色绑定支持从已启用角色选择一个备用模型。保存草稿后，在原角色下分别测试主模型和备用模型，再发布。

备用模型需要独立的模型配置，且与主模型使用同一端点策略、服务路径、供应商、协议和认证身份。两个已保存凭据版本可通过服务端解密比较验证实际 Key 一致。无认证的 Ollama 配置也可使用。主模型需要声明上下文窗口，备用模型的窗口不得更小，双方输出上限与计数配置需要一致。控制面还会检查角色启用状态、绑定环和备用链。

`DraftTestInput` 新增可选字段 `fallback_role_key`。测试会对备用模型执行原角色的探测套件，例如主对话的流式和工具往返测试。备用角色为其自身用途取得的测试结果与备用能力证据分别保存。发布检查当前草稿版本的主备证据。历史恢复重新检查密钥和发布的验证引用。

运行时先请求主模型。连接超时或允许重试的 429、500、502、503、504 在等待时限允许时切换到备用模型。两次请求共用主模型的响应头预算，仍尊重 Retry-After 和上层取消。第二次发送前检查主备的当前权限和凭据状态。收到成功响应头后进入单次响应处理，无论解析失败还是流中断，均结束该次调用。切换只更换单次模型调用的连接配置，原角色提示词、消息和工具历史继续沿用。追踪记录实际响应的模型和版本。

当前范围为同一服务与认证身份下的一次备用尝试。跨供应商、跨账号、多级切换及精确费用预算待后续设计。现有发布快照在各请求中固定。前端通过后端功能标志显示备用设置，后端加载本批代码后即可使用。

隔离后端 533 项、前端 116 项、MySQL 兼容性回归 54 项及契约检查 89 项通过，前端构建和 lint 通过。备用模型场景覆盖能力证据、端点与身份校验、上下文限制、OpenAI 兼容与 Ollama 调用、拒绝切换及撤销抢占。清理了 752 个测试临时文件，测试源码和报告保留。报告及源文件哈希见项目 `.cache/upgrade-m1l/manifest.json`。
