# M1-D：旧配置迁移草稿与三方合并

日期：2026-11-17。环境：本地开发，尚未上线。承接 [M1 发布与个人记忆记录](./M1_模型发布热更新与个人记忆_2026-11-16.md)。本轮实现 `preview-legacy`、`import-legacy` 和草稿 rebase；业务后端保持停止，未对业务库导入、授予权限、创建密钥或发布配置。

## 已实现行为

`POST /api/v1/model-config/drafts/{id}/rebase` 复用附件 E 的 RebaseInput，要求 config.edit、Idempotency-Key、If-Match 和 expected_head_version。按「草稿基线发布 / 当前草稿 / 当前活动发布」三方合并。角色绑定作为整体比较，其中的模型、凭据、提示词、跟随关系、启用状态和失败策略不会被逐字段混搭；每项 index binding 也作为整体比较，删除与修改的冲突不会被吞掉。

无冲突时保留两边各自修改，更新基线、draft_version 和 ETag。双方修改同一项时返回 40925、冲突路径和不含密钥/提示词正文的版本摘要，事务回滚，不改原草稿；调用方逐项提交 ours/theirs。重复路径或与真实冲突无关的选择被拒绝。活动 head 变化返回 40920，草稿 ETag 变化返回 40921；成功请求使用原键和原内容重试，优先返回原结果。

合并后回到 editing。运行中的旧测试及其幂等结果标为 cancelled，不再继续授权后续模型请求；已经发出的请求不能被撤回，其迟到结果无法覆盖取消状态。已通过的历史测试行保持不变，仍可作为旧发布的审计证据。新发布必须具有「本草稿、本 draft_version、相同测试目标、有效期内」的能力证据，不能借用别的草稿或合并前的通过结果。历史恢复沿用原有的离线证据校验和当前权限/端点/凭据检查。

模型配置页面增加“合并最新发布”。提交前重读当前 head；已有相同基线时不产生无意义的新版本。dirty 编辑或已发布草稿不能合并。冲突弹窗列出基准、我的草稿和活动版本，不预选任何一方；所有冲突选完才可提交。如果活动发布再次变化，清除旧选择，要求重新核对。页面显示合并后的重新测试提示。

## 旧配置迁移

`preview-legacy` 读取当前进程环境（CLI 先按原规则加载项目 `.env`，已有环境变量优先）、指定 agent/PPT YAML，以及当前模板文件。不导入数据库连接模块或旧供应商工厂，不初始化客户端，不调用模型，不依赖主密钥文件。输出每个角色的模型、地址、适配方式、启用状态、has_api_key 和迁移提示；不输出 Key、提示词正文或完整环境。

`import-legacy` 仅能由本地受控 CLI 调用，要求指定已有 active 配置管理员 UUID、已有主密钥，以及逐个 origin 指定已授权的端点策略版本。它不会因为用户名是 admin 而授权，也不会自动放行本地网段。权限、scope、策略、地址、协议、凭据归属及输入 Schema 都继续检查。

迁移规则依据当前旧工厂的实际行为：

| 来源 | 迁移草稿 |
| --- | --- |
| MODEL_PROVIDER=dashscope | 聊天使用固定 compatible-mode/v1 地址；向量保存 DashScope 原生配置 |
| MODEL_PROVIDER=ollama | 使用 Ollama 服务根地址及原生 chat/embed 协议；默认无认证 |
| CLASSIFIER_MODEL / PLAN_MODEL / VISION_MODEL / OLLAMA_VISION_MODEL / AUTOCOMPLETE_MODEL | 拆为对应独立角色；会话标题复制分类模型配置，反思按 critic_model 选择主模型或规划模型 |
| 原来共用主模型的业务功能 | 分别建立候选模型和提示词版本；后续编辑一个角色不会修改另一个角色 |
| PPT 大纲 | 保留旧代码始终使用 DashScope 的行为，即使主提供商是 Ollama |
| AUTOCOMPLETE_ENABLED / AUTO_TAG_ENABLED 及 classifier/reflection/rag 的 YAML 开关 | 保存对应启用意图；缺少云端 Key 的角色停用，不创建假 Key |
| synthesize | 保留跟随本轮执行模型和独立提示词 |
| embedding | 保存原连接和模型名称，但保持停用；维度未知保留 null，不伪造旧索引空间身份 |
| memory_extraction | 保持停用，由管理员另行配置和验证 |

未知 MODEL_PROVIDER 拒绝迁移。OPENAI_* 等旧工厂未消费的变量不会自动激活；DASHSCOPE_BASE_URL 未被旧工厂使用，预览明确提示忽略。YAML Token 预算不会被写成已验证的模型上下文容量。默认模板和部分内嵌业务提示词按当前角色契约组织，不能把迁移草稿视为与旧 SDK 请求完全等价，须人工核对及逐角色测试。

导入在一个事务中创建 request、draft、候选 profile/credential/prompt、draft_items 和 audit；任何一步失败整体回滚。凭据用既有版本化 Keyring 加密，绑定 origin 和源草稿，各角色分别持有不可变凭据版本。请求的 source fingerprint 使用 HMAC，request/audit 只存标识和摘要，不落完整来源/Key/提示词正文。凭据正文只进入加密存储，模板正文只进入模板表。

默认幂等键为 `legacy-import:system:system:v1`。相同来源和策略映射重试返回同一草稿；相同键而来源变化返回 40922。确实要再次迁移时必须显式更换键，新建另一份草稿。内部授权来源记录为 controlled_cli，actor_access_jti 和 reauth_verified_at 留空，不伪造 HTTP Token 或重新认证证明。HTTP 未开放同名导入入口或绕过参数。

导入结果只含草稿标识、版本、ETag 和待审核状态。即使已有活动发布，也只按当前 head 新建草稿，不改 head、旧发布或 Outbox，不进行收费能力测试。新草稿是一次完整迁移快照；发布前需在页面检查所有启用/停用项与提示词，尤其是向量检索停用的影响。

## 本地使用

项目根目录执行只读预览：

```powershell
.venv\Scripts\python.exe -m app.model_config.cli preview-legacy
```

可选 `--agent-config`、`--ppt-config` 指定 YAML 文件。以下导入示例仅为操作说明，本轮没有对真实业务库执行。先按前批记录显式初始化主密钥和管理员，在页面创建所需端点策略，记下它们的版本 UUID。CLI 与后端共用单配置管理器租约，导入时停止业务后端，若有旧租约须等其自然过期。

```powershell
# 云端示例：预览列出的每个 required_origin 都须有明确策略映射。
.venv\Scripts\python.exe -m app.model_config.cli import-legacy --user-id <管理员UUID> --endpoint-policy https://dashscope.aliyuncs.com=<策略版本UUID>

# 纯 Ollama 且没有云端 PPT Key 的示例：
.venv\Scripts\python.exe -m app.model_config.cli import-legacy --user-id <管理员UUID> --endpoint-policy http://localhost:11434=<策略版本UUID>
```

本地 Ollama 策略必须先明确授权实际连接地址对应的私网/回环 CIDR。Ollama 主模型与云端 PPT 混用时，需要同时提供两种 origin 的映射。导入成功后，待 CLI 租约过期再启动后端，在页面读取草稿、审核并测试；发布仍要求管理员重新认证。源内容变化时，可显式加 `--request-key legacy-import:review:2` 创建新草稿，不覆盖原草稿。
