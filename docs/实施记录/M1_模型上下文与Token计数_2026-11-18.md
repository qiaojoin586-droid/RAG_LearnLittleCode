# 模型上下文与 Token 计数

2026-11-18 实施，覆盖 M1-10 和 M1-27 的已发布模型调用。模型配置页的「高级参数」可分别保存上下文窗口、最大输出 Token 和计数方式，沿用草稿、验证与发布流程。切换模型后，新请求按新版本的窗口检查，已开始的请求继续使用其固定快照。备用模型发送前也按自己的配置检查。窗口留空的历史配置沿用原行为。

聊天在实际发送前检查最终请求，计算固定规则、角色提示词、历史、当前任务、工具调用与结果、工具描述、输入和输出 JSON Schema 及输出余量。模型窗口包括输入与输出，并留至少 32 Token 或窗口 5% 的余量。每个图像块（含视频抽帧）预留 4,096 Token，另有原生视频块预留，媒体编码后的二进制不作为文本重复计数。Ollama 原生聊天使用声明的 `num_ctx` 和输出上限。Embedding 按每条实际输入（含角色前缀）检查。

空间不足时先移除最早的完整历史轮，再依次减少整块检索、引用笔记、模板选择、历史摘要和个人记忆。当前问题、当前附件、固定规则和活动工具对话保留。检索、笔记、摘要和记忆仍以低信任数据发送。记忆被移除时，实际调用追踪记录 `omitted`，并清空选段哈希。固定内容仍放不下时，供应商调用前返回 `40008`，JSON 为 HTTP 413，聊天 SSE 发出带原因的终止错误。

保守计数按 UTF-8 字节计。已知文本编码可选 `cl100k_base` 或 `o200k_base`，服务端校验本地词表 SHA-256，缺少词表、编码未知或版本不符时使用保守计数。可在部署准备时预热词表，并给后端进程使用同一个 `TIKTOKEN_CACHE_DIR`。

```powershell
$env:TIKTOKEN_CACHE_DIR = Join-Path (Get-Location) '.cache/tokenizers'
.venv\Scripts\python.exe -c "import tiktoken; [tiktoken.get_encoding(name) for name in ('cl100k_base', 'o200k_base')]"
```

文本分词器按已选编码计数，协议封装、图片和供应商内部模板仍计入保守余量。不同模型的实际窗口、图像编码和账单由供应商响应与实测核实。任务级费用仍按已声明的窗口保守预留，完整用量返回后结算。本地测试词表位于隔离缓存，服务使用的路径与预算启用状态由部署配置决定。
