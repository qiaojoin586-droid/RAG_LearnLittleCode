# M1 模型发布热更新与个人记忆实施记录

日期：2026-11-16。本批接续 M1 控制面、配置页面和探测工作，交付文本角色发布、请求级固定快照和个人 memory.md。本地开发、尚未上线；完整 M1 与企业生产验收仍未完成。

## 可使用的页面与生效行为

- 头像 → 模型配置：管理员保存各角色模型与提示词、运行测试，然后通过发布确认和重新认证切换活动发布。页面列出启用和停用角色，未启用角色不会回退到旧环境变量模型。
- 历史发布可恢复为一个新发布。旧发布、修订号和历史记录保持不可变；恢复需要当前授权、可用的原凭据与端点策略、兼容的角色契约及原验证证据。
- 头像 → 记忆文件（`/memory`）：每位用户自己的 UTF-8 `memory.md`。支持编辑、受限预览、下载、版本查看/恢复、启停、管理模式、生成建议、采用/忽略以及清空和彻底清理历史。
- 只有访问记忆页面不会创建文件。首次允许记忆的主 AI 助手请求建立模板，手工保存也可先建立。停用后不自动重新创建或重新启用。其他笔记辅助入口不默认读取个人记忆。

发布前必须逐角色配置与验证。旧 v1 探测使用通用结构，不能证明实际业务 JSON 契约；本批使用 `role-probes-v2` / `role-contracts-v1`，旧候选提示词需要重新保存、测试。探测仍不发送个人笔记和聊天内容；固定夹具通过不代表提示词质量或真实业务效果达标。

**当前重要限制：只能发布明确停用 embedding 且不含 index_bindings 的配置。** 现有向量集合缺少可验证的空间身份，不能按模型名或维度猜测兼容性。发布文本配置后，向量检索和写入会拒绝使用旧模型/旧缓存；上层对话检索可能显示不可用后继续回答，不代表已完成知识检索。维度探针也不得绕过出站守卫。页面确认对此有明确提示；本批没有替用户执行发布或改动既有索引。

有序跨角色备用模型仍缺少原角色输出契约、上下文容量及出站范围证明，非空 fallback 列表暂时阻止发布。`follow_role` 静态共享模型和 `synthesize.follow_execution` 继续在同一发布内解析；它们与失败后切换备用模型不同。分类 `rule_only`、规划 `react_fallback`、标题 `default_title` 及辅助角色 `disabled` 的降级需符合已发布失败策略。

## 发布和推理的实现

`PublishingService` 在同一事务内检查授权、草稿/活动版本、提示词与能力证据、端点/凭据状态，然后写入 release、实际引用、审计、Outbox、幂等结果并 CAS 切换 head。发布编号使用持锁计数器。并发输家不会留下半个发布、额外事件或版本。

ASGI 中间件每个业务请求从数据库读取活动发布并构造不可变 `ReleaseSnapshot`，覆盖 SSE 全生命周期和继承该上下文的任务。新请求看到新发布，在途请求使用原模型、原提示词、原凭据版本；不会按“最新 Key”重解析。快照只保留密文，发送前按绑定身份解密，不将 Key 存入全局 SDK 设置。数据库故障明确失败；`DB_CONFIG_REQUIRED=true` 可拒绝首次发布前使用旧环境配置。

`GuardedChatModel` 实现 LangChain 异步 BaseChatModel、工具绑定、调用和流式消息。复用受控传输，支持 Chat Completions 与 Ollama 原生 `/api/chat` 的文本、工具调用和 usage 归一化；不转发隐藏推理。结构化角色实际调用时携带该角色的 JSON Schema，收到响应后再校验；记忆提取另外执行完整条件契约及来源验证。流中断不重放已输出的正文。

主对话、思考、视觉、分类、计划、补全、PPT 大纲、标题、标签、写作、回顾题、历史摘要、RAG 摘要、结果综合、反思和记忆提取均已接入对应角色解析。embedding 留在上述明确门槛后。已有活动发布时，启动不再初始化旧环境模型；首次发布前仍保留旧路径。手工迁移脚本和后续向量迁移不据此宣称已完成迁移。

每次出站重新检查账号、JWT/黑名单（交互请求）、原端点策略、凭据状态和撤销代次。后台记忆任务使用持久用户/来源授权，并在出站与结果提交处检查任务代次、head 与 epoch。原凭据撤销会阻止旧快照的新出站，已发出的网络请求无法撤回。当前还没有面向用户的紧急撤销 HTTP 接口；撤销守卫通过隔离数据库夹具验证。

Outbox Worker 使用租约、超时、最多 5 次尝试与 dead_letter。事件仅验证/刷新当前数据库发布，不用历史事件反向覆盖 head，也不发付费预热请求。多进程发布与消息通知扩展仍待单独验收。

## 个人文件、版本与提取

权威来源为 MySQL 中四张用户隔离表：heads、revisions、jobs、requests。API 无客户端 user_id 或文件路径，配置管理员也不会因此获得他人正文。下载固定 `memory.md`；成功和错误响应均 `Cache-Control: private, no-store`。预览忽略 HTML，禁用活动链接和远程图片，不加载可执行指令文件。

写操作按 User → head → job/版本加锁，检查 `If-Match: "memory-N"` 和持久幂等键。先检查同键重放，再执行新操作 CAS；正文规范 CRLF→LF 后按 UTF-8 字节限长 32768，拒绝明确凭据模式和控制字符。请求记录仅含 HMAC、版本引用和结果元数据，不存正文。7 天重放、30 天墓碑；被彻底清理的历史结果重放返回 41040。

手工保存、恢复和采用建议都建立新修订并进入手工管理，不暗中重新启用。手工管理下 AI 只提出完整候选；切回自动管理需要前端明确确认。清空递增 epoch、停用注入和提取、取消任务、移除来源及候选正文；彻底清理再按外键顺序删除历史并创建空修订，修订计数保持递增。当前已在途的请求继续其已冻结版本，不能声称清空撤回供应商已收到的数据。

成功回复与来源回执在同一 SQL 提交边界内。提交失败不发送成功确认；`memory_mode=off` 不读取/创建记忆，也不写提取来源。来源只接受本人最近 7 天、用户角色、成功对话对应消息；不会从最后一条 assistant、其他用户、工具结果、系统提示词或管理员凭据拼出来源。

有已启用提取角色时，回复提交生成唯一用户/来源任务并固定父请求发布。首次发布前可只保留成功来源回执；之后手动 generate 仍需重新验证来源。提取任务保存有限用户片段与文件基线，最多保留 7 天来源副本；每人最多 5 个 queued/running、同时 1 个 running。生成接口另限 3 次/10 分钟。租约 65 秒、单次模型调用最多 60 秒、任务截止 180 秒，未知结果不会自动重试；手动重试递增 generation。

输出必须通过 MemoryExtractionResult、32 KiB/敏感内容规则，并且每条 evidence 指向本次用户消息 ID、quote 为实际发送用户片段的连续原文。基线/head/epoch 已变更时旧结果 obsolete/cancelled；自动管理才允许 CAS 创建 model_generation，手工管理只保存 30 天候选。证据校验是必要约束，不能证明所有改写事实均正确；语义质量评测仍待实施。

## 拼接和预算

消息顺序为：固定安全 System → 已发布角色 System → 本轮任务/历史（历史摘要降为 Human 数据）→ 辅助资料 Human（RAG、引用、PPT、选定个人记忆的 JSON 框架）→ 当前问题/任务。个人记忆、检索材料和步骤结果不拼成高优先级系统授权。planner、reflection、synthesize 使用同轮选定片段，旧环境执行路径也应用资料分级。

个人记忆以 UTF-8 字节作为保守 Token 上界，默认至多 2048，已发布模型再取各可能消费者可用窗口 20% 的最小值，预留输出与 1024 固定开销。按文件次序选取、优先段落边界，不截断 UTF-8 字符。非常小的预算可省略记忆；完整问题、工具定义和历史的精确 tokenizer 总预算尚需后续统一治理，不宣称仅限制记忆即保证任意长对话可容纳。

快照记录原文件哈希、选段哈希和截断状态。model_traces.memory_context 只存版本、head、epoch、哈希等元数据；提取 trace 用 step_id 关联任务并保留原来源 request_id，不记录正文。自定义供应商缺乏已验证价格版本时费用保持 unknown；用量汇总不按任意模型同名套用旧价格，并单列未知费用次数。历史环境路径估算与完整多币种计价仍待改造。
