## 本批 API

已接入 main.py：16 个 `/api/v1/model-config` 路由及 `/api/v1/auth/reauth`。包括根状态、角色列表、草稿列表/创建/读取/替换/放弃/解析、端点策略列表/详情/创建、脱敏凭据列表、审计列表和 grant 列表/更新/撤销。列表默认 20、最多 100，返回 items、next_cursor；草稿可按状态筛选。写入要求 Idempotency-Key，修改/放弃草稿还要求 If-Match。

grant 更新输入为 `GrantUpdateInput`，撤销为 `GrantDeleteInput`，均由附件 E 校验。expected_policy_version 不符拒绝；最后一名有效管理员不可撤销或降级。

连接发现、能力探测、publish、restore、rebase、默认模板恢复、紧急凭据/策略撤销、异步请求查询、嵌入迁移等目标路由本批未注册。features.publish/hot_reload/capability_probe/personal_memory 均为 false；不会返回虚构的发布成功或进度。

## 本地初始化

以下为在项目根目录执行的显式操作说明。本轮工具未对真实业务库执行这些初始化命令，也未生成真实主密钥或授予真实用户权限。

```powershell
# 先在项目现有 .env 中确认本地 MySQL 地址，按项目流程完成迁移。
.venv\Scripts\python.exe -m alembic upgrade head

# 只创建一次。默认文件 data/config-secrets/keyring.json 已由 data/ 忽略规则排除提交。
.venv\Scripts\python.exe -m app.model_config.cli init-keyring

# 用实际已注册且 active 的用户 UUID 替换占位符，不使用用户名。
.venv\Scripts\python.exe -m app.model_config.cli bootstrap-admin --user-id <用户UUID>
```

可用 AI_CONFIG_KEYRING_FILE 指向受保护的持久文件；相对路径按进程工作目录解析。密钥首次成功加载后固定于进程，修改密钥环后须重启本阶段控制面。主密钥丢失将无法解密历史凭据；恢复时须恢复原密钥文件，不能重新初始化覆盖。Windows 本地文件权限和备份由部署者配置；生产密钥管理、轮换流程另行验收。

验证路线：登录拿 Access Token → GET model-config/roles → POST auth/reauth → 使用 X-Admin-Reauth 创建端点策略 → POST drafts → 使用 ETag/Idempotency-Key 替换角色模型、Key、提示词 → GET drafts/{id}/resolution。此时仍是草稿，不能切换业务调用。
