# M1-E：现有向量索引目录检查与待核验基线登记

日期：2026-11-17。环境：本地开发，尚未上线。承接 [M1-D 旧配置导入与草稿合并](./M1_旧配置导入与草稿合并_2026-11-17.md)。本轮完成现有 Chroma 集合的目录检查、待核验基线登记、空间比较约束和前端状态展示。业务后端保持停止，本轮只对隔离夹具执行检查和登记。

## 可用功能

新增两个本地 CLI 命令：

```powershell
# 只检查现有目录，不连接业务 MySQL、不启动 Chroma 或模型客户端：
.venv\Scripts\python.exe -m app.model_config.cli inspect-indexes

# 显式登记到配置库。仅现有 active 配置管理员可执行：
.venv\Scripts\python.exe -m app.model_config.cli register-index-baselines --user-id <管理员UUID>
```

默认目录和集合名称读取 `config/chroma.yaml`。可用 `--store <目录>`、重复的 `--collection <逻辑索引键>=<集合名>` 指定检查目标；`--tenant`、`--database` 默认分别为 default_tenant、default_database。不自动枚举或混入其他 tenant/database 的同名集合。

检查对象应处于停止写入状态。工具按普通文件读取 `chroma.sqlite3` 和存在的 WAL，在工作区 `.cache/index-inventory` 内创建临时副本；复制前后及副本内容哈希必须一致，否则返回 INDEX_STORE_CHANGED。只在副本上以 SQLite 只读模式查询，源文件不被 SQLite/Chroma 打开，也不创建源目录的 WAL/SHM。临时副本退出时清理，清理路径限制在本工具的工作区目录内。

支持的目录布局依据本机安装的 Chroma 1.5.9 迁移文件和真实 SDK 夹具验证：collections/database/segments/embeddings 的必要列齐备，SQLite quick_check 通过。布局不支持、文件不可读、目录缺失和维度异常均明确失败，不调用 SDK 自动修复、初始化或迁移旧目录。

输出仅包含存储标识哈希、目录快照哈希、tenant/database、集合名称与标识、观测维度、METADATA 段的目录记录数和核验状态。不会读取输出笔记正文、文档内容、向量数值或资源 ID 列表。目录记录数不能证明 HNSW 持久化数量、内容水位、权限一致性或召回质量；这些仍需后续索引治理与评测。

## 登记及状态含义

目录检查无法证明建库时的权重修订、预处理、归一化和输入指令，因此登记状态始终为 `baseline_unverified`。`semantic_fingerprint` 与 `build_profile_revision_id` 保持 NULL，parser_version/chunker_version 明确为 unknown；semantic_identity 中保存带 `catalog_observation_v1` 标记的观测摘要，不将它当作完整向量空间身份。

只有实际观测到正整数维度的现有集合才能登记。集合不存在或维度未知时逐项报告 skipped，不填 0、不猜维度；若全部不可登记，整个请求回滚且不创建占位索引版本。空集合以后经明确建库/写入流程确定维度后再登记。

登记复用现有 `rag_index_versions`、计数器、配置请求和审计表，无新增数据库迁移。每个 index_key 的 index_version 用行锁计数器递增；相同观测可复用原待核验版本，变化后的观测新建版本并保留旧记录。登记事务不会创建配置草稿、模型凭据、发布或 Outbox，也不会移动活动 head。

默认幂等键为 `index-baseline:system:system:v1`。同键同源重放原结果；来源变化而沿用原键返回 40922，需显式更换 `--request-key` 才能记录新观测。来源包括存储、目录快照和集合观测摘要。请求结果引用索引版本 UUID，存储哈希作为 target/审计摘要，符合 MySQL 的 result_ref 长度约束。

登记要求已有主密钥和 active 配置管理员权限，沿用单管理器租约、请求期限、事务和审计。受控 CLI 的 actor_access_jti 留空，execution_state 标记 controlled_cli，不伪造 HTTP Token/重新认证证明。未增加接收任意目录路径的 HTTP 写接口。CLI 执行时应停止业务后端并等待旧管理器租约自然过期。

新增 `GET /api/v1/model-config/embedding-status`，要求当前 config.read，可选 `draft_id`。它只读取配置库，返回已登记的最新观测、活动绑定摘要、草稿兼容性结果以及明确的 migration_supported=false/runtime_binding_supported=false；不打开本地 Chroma 文件、不调用模型。响应沿用 no-store、错误信封、JWT 和现行账户/grant 检查。

模型配置页面打开“文档与笔记向量”角色时读取状态，展示观测维度、目录记录数、待核验原因和查询绑定尚未接入的状态。未登记时提示管理员完成本地检查，失败可刷新重试，切换角色会取消旧读取。没有虚构重建百分比或可点击的迁移按钮。

## 向量空间比较

新增独立语义身份比较器。完整身份包含 schema_version、vendor、model、不可变 weights_revision、dimension、normalization、input_preprocessing、document_prefix、query_prefix、pooling 和受限 parameters。规范化 JSON 的 SHA-256 与保存的指纹须一致，实际查询配置中的模型、供应商和修订也须与身份声明一致。

Key、连接地址和超时不参与语义指纹；改动权重、模型、归一化、预处理、前缀或池化则形成不同空间。latest/unknown 等修订、维度未知、缺少身份、指纹被篡改、已退役或未核验索引均不能得到 compatible。仅名称相同、维度相同或少量样本向量相近，均不足以获得空间相等结论。

该比较器用于草稿 resolution/status 的差异判定，是后续空间绑定的必要约束；它不提供模型权重来源的自动证明。目录登记不会调用它来把未知空间升级为 verified。当前发布仍保留 INDEX_BASELINE_NOT_VERIFIED 关口，运行时仍拒绝未接通的索引绑定。
