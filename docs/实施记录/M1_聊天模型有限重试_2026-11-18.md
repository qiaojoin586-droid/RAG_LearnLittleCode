# 发布后聊天模型有限重试

2026-11-18 实施。承接 M1 模型配置发布和凭据撤销工作，覆盖 M1-18 的同端点重试部分。OpenAI 兼容聊天与 Ollama 原生聊天通过同一个网关处理流式和非流式调用。

| 场景 | 处理 |
| --- | --- |
| 连接超时或 HTTP 429、500、502、503、504 | 在读取响应体前尝试一次额外发送。关闭首次错误响应后等待。 |
| 提供 Retry-After | 接收秒数和 HTTP 日期。超过两秒、格式无效或超出本次时限时结束调用。 |
| 无 Retry-After 或连接超时 | 等待 200 毫秒，期限内才可继续。 |
| 请求写入、响应读取或协议错误 | 返回脱敏失败。 |
| 已收到 HTTP 200 | 进入单次读取及解析。正文、工具调用片段与已有工具结果沿用正常的流式边界。 |
| 上层取消或截止 | 取消等待和发送。 |

两个发送尝试和等待响应头共用模型配置的请求时限，读取响应体仍受连接客户端的读取超时及外层任务时限约束。每次发送使用同一发布快照的端点、凭据版本和请求体，并通过当前授权、凭据撤销、DNS 与连接校验。该重试发生在单次模型调用内部，工具执行器和 Agent 编排图仍处理原来的这一次调用。探测与向量调用继续使用原有请求路径和调用预算。

首次失败转入重试时记录独立的脱敏 trace，费用和用量保持未知，正常结果由原 LangChain 回调记录。429 或 5xx 响应的上游处理及实际收费取决于供应商。当前预算按最多两次尝试和单次配置输出上限控制。完整金额预算、跨角色备用模型能力证明与数据出站验收仍待完成。Retry-After 格式和读、连、写超时语义依据 [RFC 9110 §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3) 与 [HTTPX 超时文档](https://www.python-httpx.org/advanced/timeouts/)。

隔离测试使用模拟供应商验证两种聊天协议、重新发送相同工具历史、成功响应头后的流式失败、重试上限、Retry-After、连接与读取超时的区别、取消及重试前撤销。后端全量 523 项通过，含本批 27 项用例。MySQL 临时实例的 54 项回归和文档契约的 87 项检查通过。报告及源文件哈希见项目的 `.cache/upgrade-m1k/manifest.json`。清理了 773 个测试临时文件。
