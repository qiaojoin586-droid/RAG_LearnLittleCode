# M1-F：请求级向量绑定、同空间连接更新与缓存隔离

日期：2026-11-17。本地开发环境，尚未上线。承接 [M1-E 基线登记](./M1_现有向量索引基线登记_2026-11-17.md)。本批接通经人工证据核验的已有索引，从配置草稿、能力测试和发布，到请求快照中的实际 Chroma 查询/写入/删除。本轮未对真实业务库执行升级、核验或发布，业务后端保持停止。

## 新行为

发布快照同时固定逻辑索引、索引版本、Chroma 位置/tenant/database/集合 UUID、查询模型配置和凭据版本。请求受理后不重新读取活动 head；普通换 Key/超时发布只影响新请求，已有请求继续使用原模型与 Key。

当前 M1 支持 rag、notes 两个逻辑索引，二者使用本次 embedding 角色选定的同一个查询配置。索引版本可以不同，但它们必须与查询模型属于同一空间。不同知识库各自使用不同空间/查询模型，以及新空间构建和切换保留后续范围。

只有同时满足以下条件才能启用向量发布：已有集合的人工构建证据、完整语义身份、已固定的存储位置、模型/维度/凭据一致、当前草稿版本通过能力测试。目录登记的 baseline_unverified 不会自动升级或获得运行资格。

查询、入库、删除、路由距离和统计通过快照选择集合，发布路径不会落回环境变量模型或旧全局集合。Chroma 客户端只获取已有集合并禁用默认 embedding function；当前支持项目既有的显式 hnsw:space=cosine 集合，其他/未知度量拒绝查询，零向量也会被拒绝。集合不存在、UUID 被替换、存储不可用或空间不兼容时明确失败。查询限定当前用户，写入检查元数据与已有同 ID 数据的所有者，删除同时限定资源 ID 和 user_id。RAG 的数据库可见性复核继续沿用 M0 实现。

同地址、同适配器/协议、同模型与权重修订、同维度和语义参数时，替换 Key 或超时可在新候选 profile 上继承已核验空间。更换模型、修订、维度、地址或协议会清除这项继承，需重新提供证据。页面保存向量模型时同步更新已有 index_bindings 的查询配置。

M1 禁止更换已发布索引版本。检查使用历史 release_refs，恢复到最早的纯文本发布也不会清除这项约束；同空间重新接入复用原索引版本。新模型/空间只能保存为待处理草稿，不能借停用/恢复绕过索引迁移。停用向量角色可保留兼容绑定，停用后向量操作返回未配置错误。

## 构建证据及首次接入

新增本地受控命令 `attest-indexes`。它要求已有 active 配置管理员 UUID、草稿 ETag、现有基线版本、原始构建记录和显式幂等键。没有可核实的原始记录时，应保持待核验，不能从当前 .env 模型名、维度或少量相似向量补写来源。

这是管理员人工核验入口，不是自动权重证明。记录哈希用于完整性、幂等和审计，不能证明来源真实性；管理员须核实原始构建作业、固定服务修订及后续增量沿用同一空间。它不运行召回质量评测，也不能证明旧索引不存在混合空间或历史脏数据。自动来源证明与重建评测仍待后续流程。

记录格式见 [JSON 示例](../升级方案附件/12_向量构建记录示例.json)。示例含无效占位值，只展示字段。model、weights_revision、维度、归一化、预处理、前缀和池化等必须来自实际构建证据；parser/chunker/source_watermark 也不能填写 unknown。Ollama 需实际 64 位十六进制 digest；云端需可核实的固定服务修订，不接受 latest/unknown。

建议流程如下，均为操作说明，本轮未对业务库执行：

```powershell
# 先确认本地备份与新迁移，再显式升级；本批新增列均可空。
.venv\Scripts\python.exe -m alembic upgrade head

# 停止后端/写入任务，读取并登记现有目录；同键异源时显式更换 request-key。
.venv\Scripts\python.exe -m app.model_config.cli inspect-indexes
.venv\Scripts\python.exe -m app.model_config.cli register-index-baselines --user-id <管理员UUID>

# 在模型配置页准备 embedding 独立模型、端点和 Key，再停止后端进行核验绑定。
# 用页面最新草稿的完整 ETag；以下 UUID/版本/路径均需替换。
$draftEtag = '"draft:<草稿UUID>:<版本>"'
.venv\Scripts\python.exe -m app.model_config.cli attest-indexes --user-id <管理员UUID> --draft-id <草稿UUID> --if-match $draftEtag --record <真实构建记录JSON路径> --store data/chroma --index rag=<rag基线版本UUID> --index notes=<notes基线版本UUID> --request-key index-attest:review:1
```

命令重读源目录并核对 store/目录快照、集合 UUID、维度和基线观测；记录的 endpoint origin/协议须与草稿模型一致。记录 JSON 重复字段、未知字段、不完整修订或不一致集合会被拒绝。

核验在一个配置事务中创建带证据来源的候选模型与新基线版本、绑定草稿、更新版本和审计；已有已发布空间则复用原索引。旧观测和已发布 profile 不被覆盖。任一步失败整体回滚，幂等重试返回原结果。请求/审计保存证据哈希和版本标识，不保存记录文件正文、Key 或本地路径明文；实际路径只进入后端的 storage_binding。

该命令不会测试模型或发布。待 CLI 租约自然过期后再启动后端，在页面重新读取草稿、明确启用向量角色、测试并发布。若草稿含其他启用角色，按当前版本的验证要求一并测试；发布仍需重新认证。

## 协议、漂移与缓存

向量查询和文档入库分别按 query/document 生成输入，使用记录中的各自前缀；当前支持 utf8-verbatim-v1 和 provider/none/l2 归一化。DashScope 原生按用途发送 text_type，根地址自动补全 api/v1 原生路径；OpenAI 兼容模式按 index 排序恢复结果；Ollama 原生使用 api/embed。运行时按至多 10 条分批，不自动重试模型请求。

Ollama 原生能力测试和每批实际向量调用前后核对 api/tags 的模型 digest；暖缓存读取也先核对 digest。标签变化时拒绝结果，不写入 Chroma 或缓存。检查不能提供远端服务的原子锁，仍依赖供应商在一次请求中提供固定模型；其他兼容服务的修订真实性依赖人工核验和固定服务配置，真实端点兼容性仍需单独验收。

缓存 Key 包含语义指纹、维度、query/document 用途和文本 SHA-256。不同空间或不同用途不会互用缓存；同空间 Key 轮换可复用向量。缓存最多 10000 项且最多 2000000 个向量元素；缓存不包含文本或 Key。结果数量、顺序、维度、类型和有限数值检查通过，且所有分批均成功后才写缓存。

即使缓存命中，也检查用户、令牌、现行端点策略、凭据撤销 epoch 和索引状态；索引位置/身份在请求途中被改动也会拒绝。普通发布不会打断旧请求；撤销、退役和账户停用阻止后续许可。已被上游受理的效果无法撤回，许可检查后仍存在常见的在途时间窗口。

新增 embedding 追踪记录 release/profile/credential/index 版本、空间指纹和用途，正文、向量、Key 和私有文件路径不进入 trace。缺少供应商用量时保持 unknown；没有已验证价格时费用仍为 unknown。缓存命中不伪造新的模型调用或费用。完整精确计费继续按后续关口处理。

同步语义合并方法在发布模式明确拒绝直接调用旧 SDK；异步切片的线程池传递上下文。当前实际切片链路未启用该同步语义合并方法，不将它标为已迁移的异步能力。

## 数据库与界面

新增 Alembic `c346e7f8a9b0`，接在 `b235d6e7f8a9` 后，为 rag_index_versions 增加可空 storage_binding、为 model_traces 增加可空 index_context。已有观测不被自动标记为可信。存在实际绑定或索引追踪时拒绝破坏性降级；SQL NULL/JSON null 不被误判为业务绑定。

旧 a124c 迁移的恢复校验原先引用实时 ORM，新列会使重复执行误报漂移。本批仅允许识别明确的后续 storage_binding 列，有该列时仍检查其类型/可空性，其他未知字段继续拒绝。审核附件 02/08 SQL 保持原哈希不变。

embedding-status 和模型配置页现在区分待核验、人工构建记录已核验、当前发布使用的绑定及未启用状态。状态查询只读配置库，不连接模型或 Chroma，因此“当前发布使用”不表示上游此刻在线。新空间迁移仍显示未开放，不展示虚构进度。
