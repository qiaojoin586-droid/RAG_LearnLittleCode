# 聊天 SSE 断线续读

2026-11-18 接入 M2-03 的事件续读。聊天 SSE 保留原有 `type`、`content` 和业务字段。可补读的进度附加 `workflow_id`、`sequence` 和 SSE `id` 行，序号在每次运行内从 1 开始，记录提交后才发出。每次运行最多保存 256 条进度事件。

进度回放保存步骤编号、状态、工具名称和耗时等结构化字段。推理正文、工具参数与结果、临时下载地址以及未提交的回复片段维持原有可见范围和生命周期。正常完成后的续读从原会话的助手消息取正文。续读可补回步号和已提交回复，实时展示的计划描述和文件事件仍走原流，会话历史提供已保存的附件。

登录用户可请求 `GET /api/v1/chat/workflows/{workflow_id}/events?after=1&limit=50`，读取序号严格大于 `after` 的内容。默认 `after=0`、`limit=50`，单页最多 100 条。响应包含 `events`、`cursor`、`has_more` 和 `status`。只允许该会话的所有者读取，响应禁止缓存。记录随源消息删除。已结束的运行附带序号稳定的终态，成功时 `done.replay_content` 可用于恢复已经提交的正文，失败、取消或中断返回可解释的 `error`。

页面当前连接提前结束且已获得运行 ID 时，会用最后处理的序号自动尝试补读。恢复出的完整回复替换已显示的片段，聊天输入只提交一次。恢复窗口最多 60 秒，读取单次超时 5 秒。点击停止会中止当前连接或补读。短对话沿用原连接取消传播，运行一旦取消就只补读已保存进度。跨刷新自动发现、长任务脱离连接继续执行、跨进程显式取消和 Worker 恢复仍待实施。

数据库迁移 `f679ba2dc3e4` 新增 `workflow_events`。新表有联动清理及有数据时的降级保护。
