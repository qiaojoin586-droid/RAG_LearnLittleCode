# 笔记与回顾写工具的事务去重

2026-11-18 实施 M2-02 的第一批事务型工具。聊天入口先提交用户消息，再以这条消息的数据库 ID 绑定执行范围。创建笔记、更新笔记和标记回顾使用当前用户、消息 ID、工具名和规范化参数哈希识别同一个动作。模型重新生成工具调用 ID 时仍可命中该动作。不同用户消息分别计入新动作。

写工具在事务内校验当前账户、会话和用户消息归属。重复写入通过数据库唯一约束串行化。业务数据与 `tool_operations` 执行凭据在同一事务提交，提交前失败一并回滚，已提交但结果丢失时可用同一动作复用结果。凭据保存服务端生成的 `operation_id`、参数哈希、可用的发布版本和最小结果引用。笔记凭据保存笔记 ID，重放时重新检查归属及删除状态，并使用当前可见标题。回顾凭据保存回顾 ID 和已提交的下次回顾日期，重放时重新核验回顾记录。凭据随源用户消息删除。

写工具的 `tool_end` SSE 事件新增 `operation_id` 和 `replayed`，审计沿用 `tool_call_audit` 并关联同一 `operation_id`。已有聊天 `idempotency_key` 继续控制用户消息提交。重复消息键输出 `40902` 的 SSE 错误，整轮恢复与续读依赖后续检查点和事件存储。

Agent 笔记写入提交成功后才启动本次向量或标签后台工作，凭据重放跳过这些副任务。后台任务在崩溃后的补偿和索引 Outbox 属于后续阶段。邮件、文件产物和其他外部副作用的持久去重及不确定结果核对另行实施。

数据库迁移为 `d457f809b1c2`。迁移复跑核对既有表约束，存在执行凭据时阻止降级删除。本批在隔离库验证迁移，业务库仍由现有启动流程执行迁移。
