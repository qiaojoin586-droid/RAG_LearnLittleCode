# M2 凭据撤销通知丢失恢复

对应 M2-04。每个启用配置运行时的应用进程扫描本进程登记的在途凭据 ID，从数据库读取已撤销 ID 并请求取消本地 HTTP 操作。正常情况下沿用提交后的本地取消与 Outbox 投递。即使其他进程已消费事件，本地进程仍能从已提交的撤销状态恢复。空闲时无需读库。单次核验有超时，失败在下一轮重试。

配置发布后，新请求照常读取数据库活动版本。在途请求继续使用固定快照，下一次出站调用仍检查当前权限和凭据状态。本批保留现有部署方式。故障测试使用两个独立的调用登记表，一方提交撤销并消费 Outbox，另一方只能从数据库发现撤销，随后关闭自己的在途响应流。该场景随 636 项后端回归通过。
