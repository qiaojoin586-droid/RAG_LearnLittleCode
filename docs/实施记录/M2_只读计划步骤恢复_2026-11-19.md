# 只读计划步骤恢复

这批覆盖 M2-01 的步骤级恢复。后台对话的 Worker 将通过校验的计划写入 MySQL。可复用的步骤结果在发出完成事件前提交。新 Worker 领取同一工作流后，重新校验权限并加载原模型发布。输入匹配时直接进入原计划，完成剩余步骤并综合结果。

复用要求问题、纯文本会话上下文和模型角色一致。只有成功完成且不调用工具的步骤可以保存，其依赖结果也必须符合相同要求。每个结果记录实际依赖的内容摘要，依赖变化时重新计算。存在检索资料、笔记引用、个人记忆、附件或 PPT 选择的运行沿用现有只读恢复流程。涉及工具及其下游的步骤按当前权限重新执行。

检查点最多 16 KiB，每个步骤结果最多 500 字符，保存在工作流的执行记录内。成功、失败、取消或截止清理时一并删除。状态与事件补读接口不返回检查点内容。所有写入使用原有执行尝试和租约校验，已失去租约的 Worker 不能覆盖检查点。

迁移 `c902ed5fa716` 为历史工作流保留空检查点。清空存有检查点的活动任务后可回退迁移。审批、写入与外部副作用的步骤级恢复仍按 M2-02 和 M2-05 推进。

后端全量复跑 607 项、隔离 MySQL 80 项和配置契约 89 项通过。故障测试在第一步写入后终止原 Worker，将其租约置为到期，再启动新进程。新进程跳过分类、规划和已完成的第一步，使用第一步结果执行第二步，最后提交一条回复。首次全量回归中凭据撤销流出现一次超时，单项和全量复跑均通过。清理 1,549 个测试缓存和临时文件。迁移仅在隔离库执行，本地开发服务未重启。报告摘要见 `.cache/upgrade-m2g/manifest.json`。
