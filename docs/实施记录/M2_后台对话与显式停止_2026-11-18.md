# 后台对话与显式停止

2026-11-18 实施 M2-03 与 M2-04 的本地单进程执行增量。聊天输入区新增「后台继续（只读）」开关，默认关闭。启用后请求带 `continue_on_disconnect=true`，要求已有发布模型。服务先保存用户消息和运行记录，再交给受控后台任务，响应头 `X-Workflow-Id` 返回已受理的运行 ID。执行期间使用受理时的发布快照，模型调用沿用实时凭据、账户和预算校验，并额外检查运行租约。

后台模式的规划清单、计划验证和工具绑定共用只读工具白名单，覆盖时间、当前用户信息、笔记查询和回顾读取。该模式排除笔记写入、邮件、产物生成及 MCP 动作，跳过个人记忆加载、自动提取、历史摘要更新及标题生成。聊天问题和成功回复仍按对话流程保存，每用户同一进程最多一个后台对话，执行上限 180 秒。SSE 转发有独立缓冲上限，连接断开或客户端读得太慢时执行可继续，已提交的结果通过既有游标接口读取。

显式停止使用 `POST /api/v1/chat/workflows/{workflow_id}/cancel`。会话所有者通过当前权限校验后，服务原子提交 `cancelled`，再取消本进程中的任务。已结束的运行返回原终态。停止与成功提交竞态时，数据库条件更新确定结果。停止前已经发送的上游请求尽力取消，多进程路由到其他进程的取消请求返回 `DETACHED_RUN_NOT_LOCAL`，供后续跨进程取消机制接入。前端在明确停止时发送独立请求，在意外断线时继续只读补读，后台对话的补读上限 195 秒。

服务关闭时停止活跃后台对话并在 5 秒内等待收尾。进程崩溃后的未完成运行沿用租约过期与检查点查询。后续阶段增加跨进程恢复、取消传播与持久 Worker。本批沿用现有工作流表和事件表。
