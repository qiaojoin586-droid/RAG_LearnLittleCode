# 后台对话持久派发和 Worker 恢复

在本批之后，受预算限制的新任务已接入持久账本及接管。 [后台模型预算持久化](./M2_后台模型预算持久化_2026-11-19.md)

这批实现覆盖 M2-01 和 M2-04 的只读后台对话。`continue_on_disconnect=true` 时，API 在同一个 MySQL 事务中保存用户消息、附件关联和待执行记录。事务提交后返回 `X-Workflow-Id`。同一账户同时最多有一个待执行或运行中的后台对话。

应用内 Worker 轮询 MySQL 并通过行锁领取任务。领取时递增 `execution_attempt`，运行期间续租，模型出站、进度写入、终态和回复提交均校验当前尝试及租约。进程退出后，待领取任务仍可执行。已领取任务在租约到期后可以重新领取。正常关闭时先停止领取，再释放运行中的租约。

每次执行从原消息读回问题、模型选项和附件，从原发布加载模型配置，并重新校验账户、会话和原请求的授权有效期。历史消息以原用户消息 ID 为上限。任务参数只保存所需选项及会话令牌标识和有效期，终态提交时清除参数。API 不返回任务参数。

恢复尝试用原输入重新执行只读编排，并在已有事件序号后继续写入进度。首跑和重试共用受理后 180 秒的截止时间。默认最多尝试两次。启用模型请求预算时，首跑丢失租约即结束任务，避免重试重置额度。已提交的回复可通过原 ID 补读。显式停止可取消尚未被领取或正在执行的后台对话。

迁移 `b891dc4fe605` 保留历史记录原有的执行语义。回退前需清空待执行和运行中的新任务。当前 Worker 随应用运行，符合单进程拥有本地 Chroma 的部署约束。含副作用的计划仍需实现步骤输入输出检查点、审批恢复及持久预算，方可从具体步骤接续。

后端全量 604 项、隔离 MySQL 78 项、前端 SSE 17 项和配置契约 89 项通过。隔离 MySQL 在终止第一个 Worker 进程后，将其租约置为到期，验证另一个进程使用原发布恢复、顺序补读事件及只提交一条回复。清理 1,546 个测试缓存和临时文件。迁移只在隔离库执行，本地开发服务未重启。验证报告与摘要记录在 `.cache/upgrade-m2f/manifest.json`。
