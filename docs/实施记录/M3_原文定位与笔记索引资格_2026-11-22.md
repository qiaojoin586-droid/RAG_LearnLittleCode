# M3-04 原文定位与笔记索引资格

## 原文版本与切片

知识库入库完成时，在同一 MySQL 事务内提交任务状态、可检索标记和 `source_manifest`。清单记录原始文件 SHA-256、解析和切片版本，以及每段的序号、正文 SHA-256、章节、页码和字符区间。字符区间为从零开始、结束位置不含在内的 Unicode 字符索引。PDF 的区间相对于对应页面的提取文本。

检索按账号复核后，从 MySQL 清单组装 `source_locator`。文档切片 ID、文件版本和片段正文必须与清单一致。候选集合重建按已发布区间读取原文，索引切换会同时核对切片覆盖和正文摘要。

- 文档原文 `GET /api/v1/knowledge/documents/{doc_id}/chunks/{ordinal}?version={resource_version_id}`。读取原始文件时复核文件摘要和片段摘要，返回前复核当前文档权限。
- 笔记原文 `GET /api/v1/note/{note_id}/index-source?version={resource_version_id}`。版本结合索引任务修订号和正文摘要，明确当前整篇笔记的正文位置。

M3-12 起，缺少原文清单的旧文档在后台重建并发布后恢复 AI 检索。已确认账号、原始文件和模型配置可用时，可按文档加入后台重建。[双索引兼容说明](M3_双索引与授权一致性_2026-11-24.md)

```powershell
.\.venv\Scripts\python.exe -m app.rag.reconcile_cli --owner <用户UUID> --backfill-document <文档ID>
```

## 笔记检索资格

笔记编辑器提供“供 AI 检索”选项，随笔记保存提交。存量和新建笔记默认启用。取消并保存后，RAG 和笔记语义召回按最新数据库状态立即排除该笔记，后台清理旧向量。编辑、还原和重建继续尊重已保存的设置。重新启用会排队生成当前内容的索引。

Worker 在发送嵌入请求前读取笔记状态，在写入向量前按同一顺序锁定笔记和任务，并再次核对资格与版本。候选构建、历史索引追平和对账也使用该资格字段。

数据库迁移为 `d26b913f7e5c`。旧文档的定位清单按需生成。聊天引用交互和长笔记分段继续由 M3-07 与 M3-08 验收。
