# M3-12 双索引与授权一致性

一次 RAG 请求固定使用接收请求时的模型发布和向量绑定。原问题的向量、关键词和可选改写共用请求账号。检索期间切换模型，新发布从后续请求开始使用。请求期间删除文档、撤销笔记检索资格或停用账号，则在下一次授权检查时生效。

## 两类索引怎样对齐

文档和分段笔记在发布切片的同一 SQL 事务内，把关键词索引版本写入现有的原文清单。MySQL 的版本标识包含查询算法和实际的 `ngram_token_size`。每条可引用的命中仍须与原文清单中的资源版本、切片序号和正文摘要相符。

| 读取时发现的情况 | 当前请求的处理 |
| --- | --- |
| 已发布资源缺少关键词切片，或切片落后一个版本 | 排除过期切片，保留已核验的其他命中，响应为 `partial` |
| 已有切片的 MySQL 分词版本缺失或与当前配置不符 | 保留可按原文字面验证的匹配，暂停该资源的全文匹配 |
| 知识库与笔记返回不同的 SQL 索引版本 | 本轮排除两路关键词结果，保留可用的向量证据 |
| 重排前、摘要前或组装证据前，资源归属、资格或原文定位发生变化 | 移除对应证据；已组装的聊天证据在下一次模型或工具调用前失效时，中止该次调用 |

`POST /api/v1/chat/rag` 响应中的 `index_snapshot` 给出本轮的配置发布 ID、已发布的向量索引 ID 和实际读取的关键词索引版本。无配置发布的本地模式返回空的发布绑定。来源中的 `provenance` 记录各次命中所使用的索引版本。`keyword_index_lag` 和 `evidence_changed` 可分别用于定位索引积压和请求途中的资料变更。

切换向量索引、回滚发布和迁移 Chroma 存储时，服务在同一组 SQL 源数据锁下检查向量集合和关键词切片。对已发布的分段资料按页核对切片总数、序号、版本和正文摘要。验收回执记录共同的源数据水位、SQL 索引版本和覆盖数量。

## 缓存与存量资料

查询向量可以复用。重新检索、结果融合、模型出站和工具执行仍按相应阶段核验当前权限。启用 HyDE 时，可复用的假设回答按账号、登录会话、配置发布、策略和问题分区，命中时复核模型使用权限。未绑定发布的本地模式和识别出的相对时间查询会重新生成。

缺少原文切片清单的旧上传在回执中单独计数，重建完成后才能进入 AI 上下文。有原文清单、仅需补齐 MySQL 关键词版本的文档可直接重建关键词切片。两种操作均按账号和文档 ID 执行。本次本地验收使用隔离数据。

```powershell
.\.venv\Scripts\python.exe -m app.rag.reconcile_cli --owner <用户UUID> --backfill-document <文档ID>
.\.venv\Scripts\python.exe -m app.rag.reconcile_cli --owner <用户UUID> --backfill-keywords <文档ID>
```
