# M3-05 向量与关键词混合检索

## 查询路径

RAG 同时启动向量和关键词召回。关键词路使用原问题，先查完整字面匹配及型号、代码边界，再用 MySQL FULLTEXT ngram 补齐。每条命中记录 `sql_literal` 或 `mysql_fulltext_ngram`；检索方法登记为 `keyword`。向量路可沿用配置中的 HyDE。

知识库和笔记命中先检查当前账号、可检索状态、来源版本及正文，再按各路名次执行 RRF。每路最多保留 20 条。合并键包含账号、来源类型、资源、原文版本及切片 ID。相同切片只占一个候选位置，保留各路算法和名次；现有重排序随后处理合并结果。

部分召回来源报错时，保留其余已授权候选并返回 `partial` 和 `failed_sources`。全部来源失败时检索不可用。独立 RAG 接口返回召回方式、故障状态和切片的 `provenance`。需要回退时，可用 `RAG_KEYWORD_ENABLED=false` 并重启后端。

## 数据与维护

迁移 `e51a93f8c4b7` 新增 `knowledge_search_chunks`。文档的关键词切片、原文清单和可检索状态在知识库任务的同一 MySQL 事务发布。删除文档时外键级联清理关键词切片。笔记使用现有全文索引，查询遵守笔记索引资格、删除状态和当前修订。

已发布原文清单的旧文档可按原文位置补齐关键词切片，复用原文件及切片摘要。尚缺原文清单的旧文档可用 M3-04 的 `--backfill-document` 命令进入后台重建。

```powershell
.\.venv\Scripts\python.exe -m app.rag.reconcile_cli --owner <用户UUID> --backfill-keywords <文档ID>
```

## 验收范围

冻结回归集包含 12 份合成文档和 8 道检索问题，覆盖相近型号、代码标识符、中文短词和同义改写。测试使用预先固定的向量名次及实际 SQL 关键词检索，比对 Recall@5 和 nDCG@5。隔离 MySQL 8 另验证 FULLTEXT ngram、原子入库、账号隔离和删除级联。真实模型和业务语料的质量、延迟与成本按 M3-14 验收。
