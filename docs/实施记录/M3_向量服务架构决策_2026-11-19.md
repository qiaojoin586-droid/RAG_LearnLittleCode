# M3 向量服务架构决策

MySQL 保存文档、上传任务及发布进度。Chroma 保存向量与切片，文档所有权和检索资格继续在 MySQL 复核。

目标部署使用独立 Chroma 服务。后端通过受控私网端点访问，查询和写入按已发布的集合身份与向量模型选择。分离服务后可独立扩展检索和入库 Worker，向量索引切换仍须验证集合数量、权限过滤、增量水位、删除追平和恢复路径。

本地默认使用嵌入式 Chroma。M3-03 增加同机独立服务，应用和 Chroma 分别持有工作区锁和服务卷锁。应用内 Worker 继续通过 MySQL 持久任务恢复，索引写入维持一个应用进程。

## M3-03 本地切换与恢复

Chroma 客户端通过 `RAG_CHROMA_HTTP_ROUTES` 按逻辑目录选择传输方式。映射只接受 `127.0.0.1` 的端口，后端重启后生效。映射目录上的检索、入库、删除、对账和发布校验走 HTTP，现有发布版本继续验证集合 UUID、租户、数据库和距离度量。新建候选索引仍在独立本地目录构建，可以在其注册后按同一流程迁移。

1. 暂停应用及写入 MySQL 的管理任务，确保入库和笔记索引队列已经处理完。执行 `prepare`，目标父目录须存在，目标目录须全新。
2. 核对 JSON 报告。工具在 MySQL 事务内锁定知识库、笔记与任务水位，校验活动集合的源版本及删除状态，复制完整 SQLite 和索引文件。随后启动隔离 HTTP 服务复核集合 UUID、维度、数量及向量、切片正文和元数据的摘要。每个集合抽取最多 16 位用户、每位最多 2 条探针，比较按用户过滤的 Top-5 排序和相似度。校验通过才写入专用服务卷。
3. 用 `serve` 启动已验证的副本。把端口写入后端运行环境后，先执行只读对账，检查活动集合的状态和计数，再启动后端并恢复写入。服务停止时，已映射的查询和写入返回错误，避免读写切换前的旧副本。

```powershell
.\.venv\Scripts\python.exe -m app.rag.chroma_deployment prepare --logical-store data/chroma --source data/chroma --target data/chroma-http --port 8009
.\.venv\Scripts\python.exe -m app.rag.chroma_deployment serve --logical-store data/chroma --data-dir data/chroma-http --port 8009
```

在另一个终端配置后端传输与运行对账。

```powershell
$env:RAG_CHROMA_HTTP_ROUTES = '{"data/chroma":8009}'
.\.venv\Scripts\python.exe -m app.rag.reconcile_cli
```

恢复时先停止后端写入，再以 Ctrl+C 停止独立服务。用最新服务卷准备恢复副本，重新核对当前 MySQL 水位和检索。

```powershell
.\.venv\Scripts\python.exe -m app.rag.chroma_deployment prepare --restore --logical-store data/chroma --source data/chroma-http --target data/chroma-restored --port 8009
```

恢复副本校验通过后，将原嵌入式目录保留为备份，把恢复副本移到原逻辑路径。移除后端进程环境和 `.env` 中的对应映射，执行只读对账并重启后端。保留原服务卷和报告，直到核对恢复前最后写入和删除均已生效。服务进程持有卷锁，应用会拒绝直接以嵌入方式打开专用服务卷。

当前验收范围为受信任本机开发环境和单应用写入进程。跨主机访问、多写入实例、业务数据切换及大样本质量和容量指标需要独立验收。
