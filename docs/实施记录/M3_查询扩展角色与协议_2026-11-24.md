# M3-15 查询扩展角色与协议

2026-11-24，本地开发环境完成查询扩展的独立配置、发布和运行时接入。按照 M3-14 的采用决定，日常检索保留 SQL 兜底，重排和查询扩展均关闭。[四组评测与采用决定](./M3_四层检索消融评测_2026-11-24.md)

## 配置与发布

管理员进入「模型配置 → 高级业务模型 → 检索查询扩展」，可独立设置接入方式、Base URL、模型、API Key、系统提示词和任务模板。Ollama 原生使用已授权的服务根地址，可选择无认证。使用 Ollama 的 OpenAI 兼容接口时，Base URL 填到 `/v1`，高级参数中的供应商选 Ollama。模板支持 `{query}`。保存模型和提示词后，在绑定设置中启用角色，通过该草稿版本的能力测试，再发布。

| 操作 | 结果 |
| --- | --- |
| 新建普通草稿、克隆 v2 | v2，17 个角色 |
| 读取历史 v1、克隆或恢复 v1 | 保留历史 v1 的 16 个角色。新记录补入禁用的个人记忆提取角色，使用 v2 |
| 首次修改扩展角色 | 在同一事务中将当前草稿升级为 v3，增加独立绑定，首次保存连接或提示词时角色处于禁用状态 |
| 发布、克隆、合并或恢复含扩展角色的配置 | 保留 v3 第 18 个角色及其引用。恢复创建新的活动发布，在途请求继续使用原快照 |

聊天与独立检索入口读取服务端开关 `rag.query_expansion_enabled`。当前值为 `false`。即使配置页已发布可用角色，本地日常请求仍只走原有检索路径。服务端开关开启时，后续模型与提示词发布对新请求热生效。[本地配置](../../config/agent.yaml)

## 请求与降级

扩展只处理满足触发条件的原问题。模型收到固定安全规则、该角色的系统提示词，以及将原问题代入独立模板得到的一条用户消息。个人记忆、历史、笔记正文、工具和数据库授权条件均留在各自的处理环节。出站前按当前账号、端点、凭据和任务预算校验。查询扩展最多发出一次模型请求，输出上限取配置值和 384 Token 中的较小值。

模型只能返回一个含 `queries` 的 JSON 对象，最多两项，每项最多 512 字符。改写还须通过 M3-10 的约束检查。无有效结果、模型超时或临时服务失败时，保留原问题的召回，各来源继续按请求用户复核权限。任务级硬预算耗尽沿用现有终止语义。[运行时测试](../../tests/test_published_query_expansion.py)

## 验证

在独立回环端口启动 Ollama 0.31.2，使用本机已有的 `qwen3:0.6b`。首次探测时，原生和 Chat Completions 接口均用完 96 个输出 Token，未生成合格 JSON。对该角色显式关闭 Ollama 思考后，原生 `/api/chat`、兼容 `/v1/chat/completions`、兼容 `/v1/responses` 各用一次请求返回通过 Schema 校验的 JSON，各用 8 个输出 Token。兼容协议是否可用由具体模型和端点的探测结果决定。[本机协议证据](../../.cache/upgrade-m3-expansion-role/ollama-protocols.json) · [Ollama 的兼容协议实现](https://github.com/ollama/ollama/blob/main/openai/openai.go)

隔离数据库和 HTTP 协议测试覆盖发布、克隆、恢复、在途快照、凭据撤销、硬预算、非法 JSON、503 单次调用、请求体数据边界和服务端开关。前端覆盖从 v2 草稿为扩展角色独立保存 Ollama 端点及提示词。本轮协议通过后，本地 M3-14 的检索质量结论仍按冻结的四组对照记录。[本轮验收证据](../../.cache/upgrade-m3-expansion-role/retrieval/M3-15.json)
