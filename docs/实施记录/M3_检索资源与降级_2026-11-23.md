# M3-09 检索资源与降级

聊天请求在用户消息持久化后先发送受理事件。检索期间，知识库、笔记的向量和 SQL 关键词来源并行执行。部分来源超时仍可返回已到达且通过权限复核的证据。独立检索接口可以在向量服务初始化期间先检索 SQL 来源。

## 时间预算与返回结果

一次检索最多 5 秒。后台聊天会传入任务的绝对截止时间，取两者中较早者。各来源共用最多 2.5 秒的召回窗口，HyDE 在窗口内最多使用 1 秒。重排最多 1.5 秒，摘要最多 1 秒，各阶段受剩余时间约束。可选步骤最多为后续工作预留 250 毫秒。服务记录召回及初次权限核验、重排、摘要和总耗时。

| 情况 | 调用方可见的结果 |
| --- | --- |
| 所有来源正常，未命中 | 独立检索返回 `empty`。 |
| 部分来源失败或超时 | 返回 `partial`、失败来源和已核验结果，可能为零条。 |
| 可选步骤超时或失败 | HyDE 回到原问题，重排回到 RRF 顺序，摘要保留已完成项，其余使用原文。存在证据且召回来源正常时返回 `degraded`。 |
| 所有来源不可用，或最终权限复核未完成 | 独立检索返回 HTTP 503。聊天显示检索不可用并使用其他可用上下文。 |

对话中出现的检索降级提示可随持久工作流重放。该事件保存预定义状态与提示，不包含候选正文、原始异常或查询内容。

## 同步工作与取消

嵌入式 Chroma 用一个专用线程处理前台读写，允许 32 项排队。环回 HTTP Chroma 使用 4 个线程及 16 个排队位置。同步嵌入 SDK 使用 4 个线程及 8 个排队位置，重排模型使用 2 个线程及 2 个排队位置。容量耗尽时，该支路立即报告不可用。

查询取消后会放弃仍在排队的读操作，已开始的本地同步调用可以运行至退出。其容量位置到实际工作结束才释放。持有 SQL 写入保护的调用会等待 Chroma 的最终结果，防止清理或新版本写入与旧写入交错。索引构建的集合打开与关闭、嵌入式目录对账、PDF 解析、切片及文档清单计算也移出了事件循环。

同一请求中的知识库和笔记查询可以复用相同语义空间、维度和查询文本的向量。每个已发布索引仍独立校验模型权限、索引状态与绑定，Ollama 仍检查模型摘要。不同请求各自持有在途任务，编辑笔记、上传文档等写入沿用各自的嵌入流程。
