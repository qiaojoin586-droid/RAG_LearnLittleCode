# M3-13 检索预算与局部降级

服务端检索策略 `hybrid-rrf-v2` 沿用两级 RRF 的候选配额，将总时限、阶段时限及并发上限纳入同一策略版本。一次请求的排队、获取连接、生成向量和读取索引共同消耗召回时间。后台聊天还受任务本身的截止时间约束。[策略定义](../../app/rag/ranking.py)

| 环节 | 本地策略 |
| --- | --- |
| 总检索 | 最多 5000 ms，父任务先到期时使用父任务的截止时间 |
| 召回 | 最多 2500 ms，每个请求的文档、笔记、关键词、改写向量检索合计最多 4 个后端调用同时进行 |
| 可选生成 | 改写或 HyDE 最多 1000 ms。召回窗口扣除预留时间后不足 1000 ms 时直接使用原问题。改写记录原因 `insufficient_budget` |
| 重排与摘要 | 重排最多 1500 ms，摘要最多 1000 ms。阶段截止时间最多为后续工作预留 250 ms，剩余少于 1250 ms 时预留其五分之一 |
| 权限及原文复核 | 使用总预算内的剩余时间。最终复核超时，本轮不会交付检索正文 |

慢支路超时后，服务请求取消该次读取，丢弃迟到的结果。已开始关闭的传输可以继续占用资源到实际退出。单进程最多保留 64 个异步读取任务，包括正在排队和取消收尾的任务。同步 Chroma、嵌入 SDK 和重排计算继续使用各自的有界线程池。共享的查询向量在同一查询的两路读取结束后关闭。[读取任务](../../app/rag/read_tasks.py) · [检索实现](../../app/rag/rag_service.py)

## 调用方看到的结果

| 情况 | 独立检索与聊天行为 |
| --- | --- |
| 全部启用的来源完成，未命中 | 独立接口返回 `empty` 和空证据，聊天显示未找到可引用的文档或笔记 |
| 至少一路失败，另一路正常返回 | 返回 `partial`、失败来源及其余已核验的命中，可为零条。仅扩展来源命中时也可保留其证据 |
| 重排失败或超时 | 使用融合顺序，保留原融合分。独立接口的 `rerank_status` 区分 `failed` 和 `timeout` |
| 全部来源失败或总时限耗尽 | 独立接口返回 HTTP 503 和 `error`。聊天发送检索不可用提示，继续使用其他可用上下文 |
| 调用方取消或任务模型预算耗尽 | 取消向上游传播。模型调用预算和上下文限制沿用原错误契约 |

独立接口 `POST /api/v1/chat/rag` 的 `timings_ms` 给出原问题各来源、已执行的改写、重排、摘要及总耗时，单位为毫秒。单路耗时包含等待检索并发位置的时间，各路并行时耗时会重叠。聊天工作流持久化固定的检索状态和提示，客户端重连后可以重放。

## 本地验收

专项测试覆盖短父预算、过期排队任务、慢连接取消、共享嵌入关闭、重排回退、摘要模型预算及通过独立接口返回的检索状态。后台聊天用实际检索服务核验空结果、部分失败、全部失败和问候语跳过检索。[预算与故障测试](../../tests/test_retrieval_budget.py) · [后台聊天测试](../../tests/test_detached_worker.py)

2026-11-24 本地全量通过后端 814 项、前端 133 项、隔离 MySQL 8.0.42 检查 114 项及契约 Schema 用例 89 项。后端包含本轮 14 项预算专项和 4 项后台聊天入口用例。并发故障用例观测到同一请求最多同时运行 4 个检索调用，排队至截止时间的 3 个调用均未进入后端。

MySQL 试验给笔记查询注入 3000 ms 延迟，并设置 1250 ms 父预算。服务在 1014.27 ms 返回已核验的文档证据和 `partial`，慢查询连接归还后，后续关键词读取成功。固定负载使用真实嵌入式 Chroma、SQLite 关键词检索和固定向量，关闭扩展、重排与摘要。4 并发预热 8 次后，100 次混合检索 P95 为 50.12 ms，错误 0 次。[本轮验收证据](../../.cache/upgrade-m3-retrieval-budget/retrieval/M3-13.json)
