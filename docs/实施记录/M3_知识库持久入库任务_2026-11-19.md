# M3 知识库持久入库任务

本批实施 M3-06，并覆盖 M3-01 的知识库文档写入和删除路径。上传接口保留原 SSE 事件。源文件写入所属用户目录后，MySQL 在同一事务内提交待入库文档及任务。SSE 只读任务进度。浏览器断开后，Worker 仍可继续处理。使用 `X-Knowledge-Job-Id` 和 `GET /api/v1/knowledge/upload-jobs/{job_id}` 查询任务，已知编号仅对所属用户有效。同一用户重复提交相同文件时复用原任务。

Worker 从 MySQL 领取和续租，重启后可接管过期租约。重试清理此前的切片，随后以稳定切片 ID 写入向量。任务完成与文档可检索状态一起提交。删除立即撤销文档可见性，清理任务负责删除原文件和向量。失败原因和退避时间写入数据库，重试耗尽后保留失败任务供核对。

PDF 按物理页分片，每个切片记录页码和源文件 SHA-256。无法提取文本的 PDF 以 `PDF_TEXT_REQUIRED` 失败。迁移将既有文档标记为可检索。新任务在已发布模型模式下固定接收时的发布版本。文件解析与切片在工作线程执行。

M3-02 接入切换后，任务保留接收时的发布记录供追溯。实际向量写入绑定改为 Worker 持久领取后读取的活动发布，单次尝试内固定。[切换与回滚实施记录](M3_索引切换与回滚校验_2026-11-19.md)

本批沿用单进程拥有嵌入式 Chroma 的部署方式。M3 的笔记入库、全量对账、切片引用接口及外置向量服务迁移继续按验收矩阵推进。[向量服务架构决策](M3_向量服务架构决策_2026-11-19.md)

## 2026-11-22 恢复与重试验收

知识库页面重开时，通过 `GET /api/v1/knowledge/upload-jobs` 分页恢复本账号的排队和运行任务。第一页同时返回最近 20 条入库失败及其原因。任务查询可在模型配置初始化期间使用，仍要求登录和任务归属校验。

收到任务编号后，页面按编号查询进度。断网、短暂 5xx 和限流触发退避重连；重复上传返回同一编号时合并进度行。页面关闭会停止观察进度。服务端通过 MySQL 继续处理已接收的任务。原 SSE 接口继续提供阶段和完成事件。

Worker 会在每次 Chroma 写入和删除前复核并锁定当前租约，防止已被接管的旧尝试迟到写入。重试从排队和解析阶段开始。任务、文档可见状态及关键词切片仍在同一事务发布。

隔离演练在关闭上传进度流后启动 Worker，于写入 Chroma 和提交入库结果之间强制终止进程。新进程接管过期租约后完成同一任务，保留一个文档和一份切片。另验证了浏览器刷新恢复、503 自动重试、重复上传行去重，以及分页状态查询的账号隔离。
