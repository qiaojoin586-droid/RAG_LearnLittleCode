# M3 笔记索引持久任务

承接 M3-01 的笔记索引与删除清理，并为 M3-04 提供笔记来源版本校验。迁移 `4da62fb3e891` 新建 `note_index_jobs`，存量笔记及其整篇向量继续按用户归属、删除状态和正文一致性校验。

## 写入和检索

- 新建、标题或正文修改、移入回收站、恢复、永久删除和过期清理，在笔记事务内记录最新索引操作。AI 工具直写和审批执行复用相同入口。批量操作按单条保存点处理，索引任务写入失败时回滚对应笔记变更。
- 每次需要重新索引时分配独立版本，连续编辑只保留最新任务。永久删除后保留清理记录。任务表保存指针、租约与状态，正文由 Worker 从 MySQL 重新读取。
- Worker 每次领取时设置租约，超时后可由下一次领取接管。向量生成在数据库写锁外执行。写入或删除 Chroma 前再次验证任务版本和租约，再在短事务中应用向量变更并标记成功。失败最多自动尝试三次，耗尽后保留失败记录。
- RAG 和笔记语义搜索均校验用户归属、删除状态、正文和索引版本。删除事务提交后，旧向量立即失去检索资格。更新和恢复后的向量在索引成功后可用。关键词搜索继续直接从 MySQL 查询笔记。

## 本地处理失败任务

管理员可以按用户查看失败任务，并在恢复向量服务或模型配置后重排指定版本。

```powershell
.\.venv\Scripts\python.exe -m app.rag.note_index_admin failed <user_id>
.\.venv\Scripts\python.exe -m app.rag.note_index_admin retry <user_id> <note_id> <revision>
```

重排仅在用户、笔记、版本与失败状态均匹配时生效。当前绑定由 Worker 每次执行时读取，批量切换索引及追平旧集合由 M3-02 验证。

## 验证和后续

隔离 MySQL 验证迁移可重试、笔记与任务原子提交、并发领取、租约恢复和旧版本拦截。后端回归使用隔离 Chroma 及模拟 Embedding 响应，覆盖连续编辑、删除回滚、恢复、永久删除、失败重排及跨用户过滤。

M3-01 仍需验证跨索引全量对账与孤儿向量修复。段落级定位、长笔记切片和结构化解析随 M3-04、M3-07、M3-08 继续实施。
