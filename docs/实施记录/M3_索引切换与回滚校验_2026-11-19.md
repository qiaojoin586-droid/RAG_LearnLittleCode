# M3 索引切换与回滚校验

M3-02 已支持经管理员登记的独立候选集合。知识库与笔记的索引版本、查询模型和发布头在同一 MySQL 事务切换。历史发布仍可恢复，目标旧集合先通过相同的追平校验。

## 候选准备与发布

1. 按当前的切片规则独立构建候选知识库和笔记集合，保留真实建库记录。集合采用余弦距离，按笔记版本和文档切片元数据验证来源。候选集合使用独立的物理集合身份。
2. 在模型配置中准备目标 Embedding 草稿。通过现有 `register-index-baselines` 登记候选集合观测，再用 `attest-indexes --migration` 附带原始建库记录和两个观测 ID，将候选版本绑定到该草稿。
3. 在模型配置页面验证目标 Embedding 配置并发布。发现缺片、旧版本、孤儿、归属异常或未处理的索引任务时，发布会返回具体原因，修复候选集合后可以重试。
4. 恢复历史发布时，先对旧集合追平新增、修改和删除，再从版本记录执行恢复。已有请求继续使用原发布快照，新请求跟随新的发布头。

发布事务锁定来源及索引任务范围，检查两个目标集合的身份、维度、距离度量和完整性。MySQL 的范围写锁使用 `REPEATABLE READ` 或 `SERIALIZABLE`。发布审计记录校验水位、集合快照摘要和有效向量数。重新校验使用当前已提交数据，覆盖建库记录生成后发生的修改和删除。

知识入库 Worker 每次持久领取后选取当前发布的向量写入目标，并在该次尝试内使用同一快照。正在执行的索引任务会阻止切换，切换后的任务会使用新目标，即使入队请求开始于旧发布。

## 实施范围

本批交付登记与切换校验，候选构建和增量补齐采用独立维护流程。自动重建任务、持续增量同步、不同切片方案切换和冻结检索质量评测属于 M3-02 后续工作。

隔离测试使用真实 Chroma 集合和模拟 OpenAI 兼容、Ollama、DashScope 请求，验证旧数据拒绝发布、补齐后发布、旧集合落后时拒绝回滚及补齐后恢复。隔离 MySQL 检查来源范围写锁对并发插入的影响。

## 2026-11-20 后台构建和追平

管理员可以通过 `POST /api/v1/model-config/embedding-migrations` 为当前草稿启动候选构建。请求包含 `draft_id` 和 `semantic_identity`，语义身份字段与原始建库记录一致。服务校验 `If-Match`、幂等键和管理员重新认证证明，返回 `202` 与任务 ID。`GET /api/v1/model-config/embedding-migrations/{id}` 返回任务状态、候选版本和水位。

Worker 先用固定样本探测目标模型，再按批重建已提交数据。存量 PDF 使用旧版整篇切片，新上传 PDF 使用带页码的切片。文档正文先核验来源摘要，笔记按当前正文和索引版本构建。租约到期后可接管任务，集合中已经写入的切片用于续做。

任务完成首轮核验后绑定候选索引到草稿，并定时追平新增、编辑及删除。最终发布前仍由事务复核当前数据及构建状态。发布成功后，任务进入 `switched`，新写入接回活动索引 Worker。配置页可以继续验证 Embedding 并执行原有发布流程。启动构建及查询任务状态由本批新增 API 提供。

历史集合的自动追平、不同切片方案切换和冻结检索质量评测继续作为后续验收项。

## 2026-11-21 历史索引追平与回滚

管理员可以在模型配置的历史发布恢复对话框选择“追平历史索引”，并查看任务状态。API 为 `POST /api/v1/model-config/releases/{release_id}/index-catch-up`，请求体沿用 `expected_head_version`，并携带 `Idempotency-Key` 与 `X-Admin-Reauth`。返回 `202` 和任务 ID，通过 `GET /api/v1/model-config/embedding-migrations/{id}` 查看状态与水位。重复提交同一版本会返回已有的追平任务。

Worker 使用历史发布的查询模型配置、原集合身份与现有切片方式。它复用当前有效的向量，只向历史模型发送缺失或变更的内容，同时清除已删除的条目。任务支持租约到期接管，进入 `ready_to_switch` 后继续核对新增变更，直至对应集合切换为活动索引。

回滚通过原 `/releases/{release_id}/restore` 提交。服务在事务内拒绝命中写入租约或落后于当前数据的集合，校验通过后原子切换发布头并结清追平任务。后台追平针对指定版本启动，当前阶段继续验收不同切片方案切换与冻结质量评测。
