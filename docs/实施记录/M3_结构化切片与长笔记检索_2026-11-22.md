# M3-08 结构化切片与长笔记检索

新上传的文档和新建、编辑或重建的可检索笔记使用带原文位置的切片。助手可以检索长笔记末段，并从回答下方的引用直接打开命中的段落。笔记搜索仍按笔记返回结果，同一篇的多次命中取最高分。

## 切片边界

| 来源 | 切片规则 | 引用定位 |
| --- | --- | --- |
| Markdown 文档和笔记 | 识别一至六级标题、下划线式标题、围栏和缩进代码块、管道表格。表格和代码块在长度允许时整体保留，超长块优先按行拆分，单行超限时连续分段。 | 保留章节标题、块类型、字符区间及片段摘要值。表格和代码还保留整个原始块的边界。 |
| 纯文本和普通段落 | 当前配置每片最多 1,024 个 Unicode 字符，正文目标重叠 150 个字符。优先在段落、行或句子边界断开。 | 区间直接对应原文，偏移从零开始，结束位置不含在片段中。 |
| PDF | PyMuPDF 按物理页提取文本。纯图页跳过，混合文档余下各页沿用原页码。整份缺少可用文本时任务记录 `PDF_TEXT_REQUIRED`，加密且需要密码的文件记录 `PDF_PARSE_FAILED`。 | 页码从 1 开始，字符区间基于该页提取的文本。图片文字识别和 PDF 表格版式还原不在本次覆盖范围内。 |

## 发布与读取

笔记后台任务把同一版本的切片写入 Chroma。每个向量批次写入前会检查任务租约及笔记状态。所有向量就绪后，后台任务在同一个 SQL 事务里替换关键词切片、发布原文清单并标记成功。任务重试会清理该用户该笔记的残留向量，缩短或删除笔记会清理旧段落。

向量与关键词命中均核对当前用户、检索资格、版本、切片 ID 和内容摘要。两路命中同一段时融合为一条证据，未启用摘要时给模型传入该片完整原文，整轮仍受上下文预算约束。引用打开时再次核对版本和位置。候选索引重建和对账也读取同一份已发布清单。

## 既有资料

本轮数据库迁移增加可空清单和笔记关键词切片表。已有整篇笔记和旧文档继续使用原索引，既有引用按其发布版本校验。下次更新笔记后会生成新版本。若需提前转换某条已有笔记，可在项目根目录执行以下命令，由笔记索引 Worker 异步处理。

```powershell
.\.venv\Scripts\python.exe -m app.rag.note_index_admin rebuild <user_id> <note_id>
```

重建会使该笔记之前版本的引用失效，重新检索后可生成分段引用。文档的存量重建沿用已有流程。[原文定位与存量重建](M3_原文定位与笔记索引资格_2026-11-22.md)

## 本地验收

开发库已迁移至 `ce28a435b197`。首次建表时，服务器默认排序规则与旧笔记主键不同，外键创建失败。修正后的迁移读取主键实际排序规则，复用已添加的列并完成建表。恢复前后均有 17 篇笔记、4 份知识库文档、267 条聊天消息。符合重建条件的 12 篇旧长笔记保留原索引，本次迁移新增 0 条切片。

隔离测试覆盖真实 Chroma 集合、MySQL 8 中文全文索引、纯图及混合 PDF。长笔记案例把唯一编号放在最后一个章节的第 800 个字符之后，验证两路召回、模型上下文、回答引用、原文读取和重建结果一致。中断用例验证只写入首批向量时的新版本不可见，重试后切片数与关键词表一致。测试使用确定性的向量，模型检索质量由 M3-14 的冻结题集另行衡量。[本轮验收证据](../../.cache/upgrade-m3-structural/faults/M3-08.json)
