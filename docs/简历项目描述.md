## 二、⭐ 核心闪光点（面试 30 秒亮点速讲）

按「亮点 → 一句话价值」组织，面试开场任选 2–3 条展开：

1. **自研双 Agent 混合路由，而非套 LangChain 模板**：L1 规则 + L2 轻量模型分类器两级分流，简单问题零成本直答、复杂任务自动规划执行、计划失败无缝降级 ReAct（SSE 契约不变，前端无感知）——兼顾推理质量、响应延迟与 Token 成本。
2. **AI 产品的质量用评测闭环保证**：自研「AI 对话黄金评测器」，24 条黄金用例（含 Prompt 注入等安全用例）自动跑真实 SSE 对话并判定 PASS/FAIL，可随时回归——个人项目里少见的「大模型应用有自动化回归测试」。
3. **全链路可观测 + 成本治理**：model_trace 输出总线（log / db / Langfuse 三通道可切换）记录每次模型调用的 Token、延迟与费用，叠加 Prometheus 指标与用量账单 API——每一分模型开销可审计、可优化。
4. **行为配置外置的「可调参 Agent」**：4 个 YAML 行为配置 + 12 个提示词文件 + 65 项环境变量，路由规则、Token 预算、各阶段超时、记忆阈值、MCP 白名单全部零代码调优——Agent 调优不碰代码，迭代快。
5. **多模型角色分工**：Chat / Thinking / Embedding / Vision / Classifier / Plan 各司其职、独立配置，DashScope（云）⇄ Ollama（本地）一键切换；分类、规划等高频环节用轻量模型分流，重活才上强模型。
6. **用实测数据做工程决策**：多模态 + 深度思考的 60 秒超时问题经实测定位后，设计为「附件场景强制视觉模型 + 自动关思考 + SSE 同步提示」——体现测量驱动的产品化权衡能力。

## 三、🏗️ 架构亮点（面试深挖素材）

分层拆解，每条按「设计 → 收益」讲，面试被追问时逐层展开：

### 3.1 编排层 —— 一张图跑两种 Agent，路由可测、降级无感

- **LangGraph 单图双路径**：`classify → 条件边 → ReAct / Plan-Execute`，StateGraph 编译一次全局复用；路由决策收敛为纯函数 `decide_route`，可单元测试。
- **事件总线解耦**：图节点把事件推入 state 内 `asyncio.Queue`，SSE 格式化由调用方完成——编排逻辑与传输协议解耦，`plan_fallback` 降级重跑 ReAct 时 SSE 契约不变，前端零改动。
- **L1 规则 + L2 LLM 分类器混合路由**：规则命中零成本直达；模糊问题交给轻量模型（默认 qwen3-flash）精判，未配置时自动回退主模型——简单问题不浪费强模型，复杂任务不被规则误伤。
- **容错设计**：Plan 模型不可用、计划执行失败、MCP Server 故障三层降级，保证「可用性不随复杂度上升而下降」。
- **Reflection 自省闭环**：Plan 结果合成后接「生成 → 批判 → 修正」单轮自检（轻量批判模型 + 反射指标落盘），核心原则 fail-safe——批判解析失败 / 超时一律放行，反思是增强不是关卡。

### 3.2 模型层 —— 角色分工 + 提供商抽象

- Chat / Thinking / Embedding / Vision / Classifier / Plan 多模型独立配置，DashScope ⇄ Ollama 一键切换；分类器、计划生成用轻量模型分流，控制成本。
- 附件场景强制走视觉模型并自动关闭深度思考（实测 61.9s 首 Token 超时驱动的设计），SSE 同步提示用户——多模态与思考模式的互斥以产品化方式消化。

### 3.3 检索层 —— 混合召回 + 重排序，兼顾语义与精确

- 链路：HyDE 假设性文档增强 → ChromaDB 向量 + BM25 关键词混合召回 → BAAI/bge-reranker-v2-m3 重排序 → LLM 摘要，解决纯向量检索对精确术语不敏感的问题。
- 启动时自动校验 Embedding 维度与向量库一致性；切换 Embedding 模型提供**无损重嵌迁移脚本**（读原文 → 重建集合 → 重新嵌入），避免"换模型就重建知识库"的隐性成本。

### 3.4 工具层 —— 注册表 + 按需加载 + 全链路审计

- `ToolRegistry` 统一管理 9 组 15 个内置工具 + MCP 动态工具（白名单注册进 "mcp" 组）；关键词路由按需加载 + 全量兜底，工具描述只注入用得到的那部分，省上下文窗口。
- 每次工具调用**审计落库**（tool_audit 表），可回溯"哪个工具、哪次对话、什么参数"；MCP Server 故障自动降级跳过，不影响 Agent 主流程。

### 3.5 记忆层 —— 三级压缩 + Token 预算

- 滑动窗口 + 里程碑摘要 + Redis 热缓存三级记忆压缩：近期原文、中期摘要、历史冷数据分层存取，长对话不丢上下文；
- 配合 Token 预算管理，上下文成本有上限、可配置。

### 3.6 工程化 —— 可观测、可评测、可部署

- **可观测**：model_trace 输出总线（log / db / Langfuse 三通道可切换）请求级记录 Token / 延迟 / 费用；Prometheus `/metrics` 指标。
- **协议设计**：SSE 14 类事件（`thinking` / `tool_start` / `plan_step` / `tool_file` / `plan_fallback`…）+ 请求幂等键，nginx 禁用缓冲保证流式体验；前端据此渲染思考过程、工具卡片、PPT/TTS 下载卡片。
- **可评测**：黄金评测器逐条跑真实 SSE 对话按关键词判定 PASS/FAIL，覆盖对话 / RAG / 笔记 / 多模态 / 安全注入分类，纳入 CI 回归。
- **可部署**：Docker Compose 一键启动，健康 / 就绪探针 + 数据库自动迁移（alembic）；生产加固：JWT 强校验、SSRF 守卫、邮件限流、孤儿附件与回收站定时清理。

## 九、面试追问素材（真实故事，展示解决问题的能力）

每个故事按「发现问题 → 定位 → 修复 → 沉淀」讲，面试时选 1–2 个即可：

1. **多模态 + 深度思考的 60 秒超时**：思考模型加大图输入时首 token 延迟实测 61.9s（超时阈值 60s）。方案：带附件请求强制切换视觉模型并自动关闭思考模式，SSE 同步提示用户——体现实测定位 + 产品化权衡；
2. **视觉模型接线偏差**：初版把附件直接喂主模型，违背「视觉模型分离」的设计意图，经双实例分工修复——体现对照设计 + 回归修正；
3. **时区 bug**：消息表 created_at 一处 UTC、一处本地时区，导致孤儿附件清理定时任务失效 8 小时——体现对数据一致性的敏感与排障能力；
4. **评测用例设计**：首轮 22 条用例 20 通过（90.9%），2 条失败源于用例歧义（如「第几大行星」按大小 / 按距日两种口径）而非系统缺陷——修正用例本身而非迁就实现，并扩充至 24 条后全量通过——体现评测方法论；
5. **Plan-Execute 重复输出修复**：多步骤计划中不同步骤可能输出相同的大段内容，导致最终回答重复；通过步骤结果归一化去重 + 文本包含关系保留较长者（`_dedupe_step_results`）修复——体现对 Agent 输出质量的把控；
6. **Reflection 反思机制落地**：按设计方案实现「生成 → 批判 → 修正」单轮自检闭环（L1 综合后自检 + 反射指标落盘），核心原则 fail-safe——批判解析失败 / 超时一律视为通过、绝不阻塞回答（设计文档见 [AI对话Reflection反思机制设计方案.md](设计方案（不可提交）/AI对话Reflection反思机制设计方案.md)）——体现"先设计后实现、增强功能不降可用性"的工程习惯。
